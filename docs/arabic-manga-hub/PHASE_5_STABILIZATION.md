2026-11-07 (الرياض). الأساس `9c5709014d12623738daff5f6c17ae805dfb2e43`، الفرع `feature/arabic-manga-hub`. لا دمج في master ولا مرحلة سادسة.

## السبب والتصحيح

كان `queue-open` يثبت الوجهة والسياسة فقط، ثم يقرأ `queue-next` كل العناصر المنتظرة عند كل دورة. لذلك كان يمكن للإضافة أثناء تنزيل عنصر أن توسع العمل الذي وافق عليه المستخدم. لم يكن مجرد تثبيت أعلى seq كافيًا: إعادة إضافة صف قديم تستعمل seq نفسه.

يضيف SQLite **v10**، بعد v9 المنشور ودون تغييره:

- `hub_queue_batches(id,confirmed_at)` لسجل التأكيد.
- `hub_queue_batch_members(batch_id,queue_seq,enqueue_version)` لعضوية المجموعة المؤكدة.
- `hub_queue.enqueue_version`، يزيد عند إعادة عنصر أزيل من القائمة، دون تغيير هويته أو جلسته أو إيصالاته.
- `hub_queue_control.batch_id` لربط التشغيل والاستئناف بالمجموعة الدائمة.

يأخذ Start المؤكد لقطة عضوية في معاملة واحدة. يستعمل queue-next تقاطع المجموعة مع إصدار الإدراج الحالي، والعناصر غير المزالة والمؤهلة، بترتيب القائمة. إضافة جديدة أو إعادة إضافة صف قديم تبقى للعملية التالية. الإضافة المكررة لعنصر ما زال في القائمة تظل متكررة آمنة ولا تلغي عضويته. يمكن إزالة عنصر غير جارٍ أثناء التشغيل، لكن لا يمكن تعديل ترتيب القائمة أو إزالة المهمة النشطة قبل إيقافها.

Pause وInterrupted وLimited وFailed تستأنف المجموعة المحفوظة؛ لا تضم الإضافات اللاحقة. بعد Drained أو Cancelled يحتاج التشغيل التالي تأكيدًا جديدًا، ويثبت مجموعة جديدة دون إعادة ميزانية 5/20. انتهاء المجموعة الحالية لا يتحول إلى Limited بسبب عناصر أضيفت خارجها؛ تبقى هذه Queued وتظهر بأنها تنتظر تأكيدًا لاحقًا. تبقى ملفات المستخدم والإيصالات والجلسات ومحاولاتها دون حذف أو تصفير. المجموع التراكمي ما زال يشمل الجلسات المزالة والمكتملة، والاحتياطي 50 GiB على الأقل.

لا يمكن استنتاج عضوية تشغيل v9 قديم من بياناته الحالية. الترحيل يضع حالة التحكم القديمة المفتوحة في Review، دون اختلاق مجموعة أو تشغيل تلقائي. يحتاج بدء مجموعة جديدة إلى تأكيد صريح. تُحفظ باقي البيانات، واختبار فشل الترحيل يثبت رجوع ALTERs معاملاتيًا إلى v9 بلا نصف مخطط.

## All وMissing

الوضعان متطابقان وظيفيًا حاليًا: نفس manifest المكتشف، مع تحقق الاستعادة وإعادة استخدام الملفات السليمة. أبقينا missing للتوافق مع السجلات المحفوظة، وسمّته الواجهة صراحة اسمًا قديمًا مكافئًا لـAll. أضيف شرح دائم أن الاستئناف لا يوسع manifest محفوظًا ولا يكتشف فصولًا أضيفت بعد اكتماله. لم يتغير الترتيب أو Review، ولم تنفذ إعادة فهرسة أو توسعة manifest أو تنزيل قسري.

## الملفات

- `ArchiveSchema.ts`, `SelectiveQueueRepository.ts`, `SelectiveQueueContract.ts`: الترحيل والعضوية وإصدارات الإدراج وعقود العرض والنطاقات.
- `SelectiveQueueRunner.ts`: توثيق ملكية المجموعة في الرئيسي؛ حلقة التنزيل تستخدم ArchiveManager الأصلي دون محرك جديد.
- `PersonalQueue.svelte`: حالة التأجيل، وصف النطاقين، إزالة غير الجاري، وتنبيه التوافق مع قواعد أقدم.
- `SelectiveQueueRepository_test.ts`, `SelectiveArchiveSource_test.ts`, `test/selective-queue-renderer.mjs`, `test/archive-runtime-entry.mjs`: التراجع، الاستعادة، إعادة الإدراج، الميزانيات والملفات. تغيرت توقعات **الإصدار الحالي** في اختبارات الترحيل السابقة إلى v10 دون تغيير تأكيدات حماية البيانات التاريخية.
- `.github/workflows/windows-preview.yml`: دعم دفع فرع المركز، والفحص الساكن وتكامل Electron واستعادة SQLite، ثم بناء حزمة جديدة وتشغيل EXE الحقيقي، مع منع اختيار ZIP من التزام آخر ورفع الحزمة المختبرة وحدها.
- `test/windows-preview-smoke.mjs`, `test/preview-legacy-profile.mjs`: إعداد ملف تعريف اختبار قديم معزول، وفحص التطبيق المجمّع وترحيلاته والمركز والفهرس والبحث والقائمة وإعادة التشغيل ومطابقة مصدر الحزمة وSHA-256.
- `app/electron/scripts/package-windows-preview.mjs`: تنبيه التوافق في START-HERE؛ لا تغيير لمسار العزل أو تحميل الواجهة المحلية.

## Windows Preview ومصدر الدليل

سير Windows المحدّث يعمل تلقائيًا عند دفع `feature/arabic-manga-hub`. يبني من checkout نفسه، ويقارن `Preview::Info.commit` مع HEAD، ويختار ZIP باسم بادئة SHA نفسها، ثم يشغّل EXE المستخرج على Windows. لا تُرفع الحزمة إلا بعد نجاح الاختبارات وتشغيل EXE؛ يرفق SHA-256 وتقرير `preview-smoke-win32.json` وملخص الالتزام والمخطط ورابط Artifact. الاحتفاظ بالـArtifact 14 يومًا وفق إعداد السير.

لم نستخدم حزمة فرع Windows السابق. نتيجة Windows ورابط التشغيل النهائي والحزمة يُرفقان في تسليم هذه المراجعة عند توفرهما. وصول GitHub API من بيئة العمل الحالية محجوب؛ قراءة صفحة Actions العامة متاحة، ولا تُفسر المصادقة الفاشلة في gh كدليل فشل بناء Windows. لا تُدّعى نتيجة Windows دون التحقق من صفحة التشغيل الفعلية.

## تنبيه البيانات والتجربة اليدوية

**SQLite v9 أو أحدث قد تمنع العودة إلى Preview قديمة. قبل ترقية ملف تعريف Preview موجود، أغلق التطبيق وانسخ مجلد بياناته كاملًا بصورة متسقة. العودة تتطلب نسخة بيانات الإصدار السابق؛ لا تحذف القاعدة ولا تخفض PRAGMA يدويًا.** استخدم ZIP جديدًا داخل مجلد مستقل قابل للكتابة، ولا تنسخ بيانات HakuNeko الأصلية إليه. شغّل `Start-HaruNeko-Enhanced-Preview.cmd`؛ بياناته تحت `haruneko-preview-data` بجوار EXE.

على Windows تحقق من BUILD-INFO والالتزام المعروض، وظهور Arabic Manga وDownload Queue، وبقاء الإعدادات والمفضلة الأصلية مستقلة. اختبر البحث المحلي والتحديد عبر استعلامين والإضافة الفردية والجماعية. عند تجربة قائمة صغيرة مصرح بها، أضف ثالثة أثناء الأولى؛ يجب أن تنتظر تأكيدًا لاحقًا. أوقف التطبيق واستأنف المجموعة نفسها، ثم افحص All/Missing ورسائل Review. لا تحاول إجبار مصدر غير موثق الترتيب؛ كثير من الموصلات لم تعتمد اتجاهاتها بعد. اختبارات CI المعزولة لا تثبت سلامة الصور الحية أو اكتمال المصدر، ولا تحل محل تجربة المستخدم المحدودة.
