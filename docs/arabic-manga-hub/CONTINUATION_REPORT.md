# متابعة الفهرسة والتنزيل الانتقائي والتفاصيل والبحث

2026-11-08 — `feature/arabic-manga-hub`، الأساس `16461312836153403659aa7d8874894333984b63`.

## المنفذ

استكمال للأنظمة الحالية، دون إعادة إنشاء المركز. تحديث الفهارس يظل منفصلًا عن الفصول والصور. التنزيل الانتقائي يستعمل ArchiveManager وDownloadManager والاستعادة وحماية التخزين القائمة. لم تتغير حدود5/20 أو احتياطي50GiB أو ترحيلات SQLite؛ المخطط ما زال v10.

### الفهرسة والمهلات

كانت المهلة60 ثانية للعملية كلها؛ MangaSpark يعيد مصفوفة بعد إتمام صفحات Madara AJAX، فلا تصل دفعات التسجيل إلى مدير الفهرسة أثناء الطلبات. لذلك قد تفشل محاولة سليمة طويلة قبل نشر أي مرجع.

أصبح هناك حد أولي180 ثانية للتهيئة/أول نتيجة، ثم مهلة خمول60 ثانية تتجدد **فقط** عند ورود عناوين من صفحة ناجحة، مع حد إجمالي30 دقيقة للمحاولة. وصول headers أو heartbeat وحده لا يجددها. تبلغ Common CSS وMadara AJAX وDilar عن تقدم صفحات الفهرس؛ المصادر المعتمة التي لا تبلغ تقدمًا تبقى محدودة ولا يُفترض تقدمها.

MangaPlugin يجمع طلبَي الجلب اليدوي والجماعي المتداخلين للموقع نفسه في سلسلة أصلية واحدة. الإلغاء يصل إلى طلبات CSS/Madara المملوكة للمحدّث، ولا يلغي مستهلكًا يدويًا مستقلًا للسلسلة نفسها. لا يُحرر قفل التشغيل قبل استقرار النقل الفيزيائي؛ المصادر القديمة التي لا تتعاون مع AbortSignal قد تبقى في draining حتى ينتهي طلبها، مع حفظ الإيقاف وعدم نشر رد متأخر.

تُرصد حالة HTTP للطلبات التي تمر عبر المسارات المجهزة دون قراءة headers الحساسة أو حفظ URLs. لا تُنشر روابط صفحة خطأ401/403/429/5xx كفهرس ناجح؛ الرفض/التحدي/تحديد المعدل لا يسبب إعادة محاولات عدوانية. آخر صفحة ترقيم404 مع ملاحظات سابقة قد تبقى قائمة جزئية، ولا تثبت الاكتمال. التغطية والأعداد القديمة تظل محفوظة بمعاملة IndexedDB ومراجعة تمنع استبدال تحديث يدوي أحدث.

### السجلات

لكل عملية بدء منفردة أو جماعية UUID وملف JSONL في مجلد Electron الخاص بالتطبيق: `logs/arabic-manga/`. الاستئناف يضيف أحداثًا للعملية نفسها. زر Open Logs في Sites يفتح المجلد الأصلي فقط؛ لا يقبل IPC مسارًا حرًا.

يسجل begin/resume، نوع full-refresh، حالة الفهرس السابق، المحاولة والموقع والاسم والمدة، التقدم، النجاح والفشل ومرحلة الخطأ والتغطية والعدد المحفوظ، ومقارنة added/changed/unchanged/retained وملخص حالات المواقع. HTTP يسجل عندما تتوفر ملاحظة فعلية؛ القيمة null تعني غير معروف. التشخيص مصنف ويحتفظ بنوع الخطأ دون تسريب رسالة شبكة خام قد تحتوي أسرارًا.

تكتب الأحداث تدريجيًا مع fsync، وتخفف أحداث التقدم إلى حدث في الثانية. الحد التقريبي2MiB للملف، والاحتفاظ30 يومًا وبحد30 ملفًا سابقًا بالإضافة إلى الجاري. لا تُمس الأرشيفات أو قواعد البيانات ضمن التنظيف. عند تحليل ملف انقطع التطبيق أثناء كتابته، يمكن تجاهل سطر JSONL أخير ناقص. فشل التسجيل لا يفشل التحديث؛ آخر فهرس صالح مستقل عن السجل.

### قرار Quick Update

**لم يُضف خيار شكلي.** عقود FetchMangas الحالية ترجع id/title دون cursor تغيير موثوق أو تاريخ تعديل عام. Madara وCSS يحتاجان اجتياز القوائم؛ ProChan يستعمل طلب search محدودًا، وDilar يرقّم series. المعرف المستقر يفيد المقارنة والحفظ، لكنه لا يثبت عدم تغير عنوان سابق أو عدم ظهور عناصر في صفحات لاحقة. التوقف عند أول هوية قديمة أو تساوي العدد يمكن أن يفقد تغييرات.

Update وUpdate All ينفذان full-refresh: إعادة فحص المصدر، لا حذف المكتبة أو تنزيل صفحات. تُحفظ المقارنات في السجل وتبقى المراجع القديمة غير المرصودة. Quick Update حقيقي يحتاج قدرة خاصة موثقة في الموصل ودليلًا على سلامة مؤشر التغييرات واختبارات له قبل إتاحته.

### Chapter Order واختيار الفصول

قائمة Chapter Order لكل بطاقة تحوي Source Order الافتراضي وFirst → Last وLast → First؛ الاختيار متنافٍ ومحفوظ في نطاق الطلب داخل SQLite. اختلاف الموصلات يسمح بسياسة مستقلة لكل مانجا. الترتيب نفسه يحدد العرض والتنفيذ الفعلي، وليس عكس قائمة واجهة فقط.

Source Order يقبل تسلسل المصدر عند التشغيل الصريح دون ادعاء تسلسل زمني. الاتجاه الزمني يحتاج دليل الموصل أو تأكيد المستخدم أن المصدر يصعد/ينزل؛ النطاق الرقمي لا يستخدم أرقامًا مخمنة من العناوين. الأسماء الخاصة والكسور تبقى كما أعادها المصدر.

زر Chapters يجلب مراجع الفصل عند الطلب فقط، أو يقرأ manifest الجلسة المحفوظة؛ لا يفهرس فصول كل المواقع تلقائيًا. القائمة داخل البطاقة، بارتفاع محدود وتمرير، وحالات منفصلة وأسماء أصلية ومربعات اختيار وSelect All/Clear Selection. الاختيار الأول يشمل الجميع، والمتفرق يحفظ بالهوية، لا بالموضع. صفر اختيارات لا يفتح مهمة ولا يستهلك الميزانية أو يوصف بفشل مصدر. تغيير الترتيب لا يغيّر مجموعة الهويات المحددة. تحديث العرض بعد تعديل الاختيار متسلسل مع الحفظ لمنع البناء على اختيار قديم.

الاختيارات والسياسة الحقيقية في hub_queue.scope؛ كاش العناوين للعرض فقط في Store.Settings. تستعاد الحالة بعد إعادة الفتح. manifests القديمة لا تتوسع تلقائيًا، ولا يحذف غياب هوية من العرض اختيارها المحفوظ؛ الهوية المفقودة تحتاج مراجعة قبل التنفيذ.

تحتفظ البطاقة بكاش أسماء الفصول غير المختارة أيضًا وتحدّث حالات الفصول المسجلة من SQLite أثناء التشغيل. استبعاد فصل كان سليمًا يغيّر أهلية تنفيذه فقط، ويحفظ إيصال الملف وحالته المحلية؛ لا يُعاد تنزيله لأنه غير مختار. إذا أُعد أول manifest لنطاق فرعي، فإعادة تضمين هوية لم تُسجل فيه تُرفض صراحة بدل عرض Select All بوعد تنزيل غير منفذ؛ توسعة manifest محفوظ عمل مستقل يحتاج مراجعة.

يمكن تحميل جلسة قديمة محجوزة بسبب unknown-order ثم Apply Source Order to saved task أو اختيار اتجاه مؤكد. يتغير تسلسل العمل المعلق بمعاملة واحدة مع حفظ هوية الجلسة والفصول والإيصالات والمحاولات والميزانية. تُرفع مراجعة **unknown-order وحدها**، وتُعاد قواعد اللغة قبل السماح بالتنفيذ. لا تُرفع تعارضات الهوية أو مراجعة الترتيب التاريخي v8 أو أعطال الاستعادة لمجرد تغيير القائمة. الملفات السليمة تُستعاد وتُعاد الاستفادة منها؛ لا إعادة تنزيل لمجرد عكس العرض أو إعادة التحديد.

### Download Manga Details

مربع واحد غير مفعل افتراضيًا، محفوظ في الإعدادات القائمة. السياسة تؤخذ عند بدء التشغيل، ولا تتغير أثناء المهمة. بعد محاولة الفصل/المانجا، تُجرى محاولة مستقلة محدودة15 ثانية للمعلومات الاختيارية من مصدرها المختار؛ فشلها لا يغير نتيجة الفصول ولا يمنع متابعة القائمة.

تستعمل OpenGraph وJSON-LD وحقول Madara المعروفة عندما تتوفر: عنوان، أسماء بديلة، وصف، مؤلف، رسام، تصنيفات، حالة، رابط المصدر وعدد الفصول المسجلة المعروف. العدد المسجل ليس شهادة عدد فصول المصدر. لا تُخترع حقول غائبة أو علاقة بين عملين؛ JSON-LD لعمل آخر لا يزود العمل المختار بأسماء بديلة. تُرفض هويات عددية أو URLs تعتمد على query غير مفهوم بدل تخمين صفحة مانجا أو إسقاط معرّفها. هذا استخراج اختياري، وليس دعم metadata مخصصًا لكل موصل.

الحد2MiB لصفحة التفاصيل و8MiB للغلاف، مع قراءة محدودة وإلغاء. الغلاف يمر عبر ValidateImage، ثم تحقق Electron، وامتداده مشتق من التوقيع. فشل الغلاف يحتفظ بالنص، وفشل حقل لا يسقط بقية الحقول.

الحفظ في مجلد المانجا الرئيسي تحت `00 - Manga Details`: details.txt وغلاف بامتداده الصحيح، خارج الفصول وCBZ/EPUB/PDF. هوية المجلد وتعارض اسم مانجتين وفحص الجذر والمسارات والروابط الرمزية وحماية المساحة مطبقة في الرئيسي، دون مسارات من الواجهة. الكتابة exclusive؛ لا حذف أو استبدال ملف موجود مختلف. تبقى حالة Saved/Partial/Unavailable والإيصالات SHA-256 مستقلة في نطاق القائمة، ولا تؤثر على اكتمال الفصل. الغلاف السليم بإيصاله لا يُجلب مجددًا، والنص المطابق لا يعاد استبداله. تغير محتوى ملف قائم يحتاج قرارًا لاحقًا؛ لا تُكتب نسخة مختلفة فوقه ضمن هذه المهمة. النشر ليس معاملة ملفات ذرية مضمونة؛ ملف جزئي غير مطابق يبقى محميًا للمراجعة.

### البحث

المحرك المحلي والعامل الخلفي والفهارس نفسها باقية. أضيفت تسوية ياء/كاف فارسية مع التطبيع العربي القائم، وحد تشابه يقلل أخطاء الاستعلامات القصيرة. المطابقة الدقيقة تتقدم التقريبية. اختيار أفضل نتائج الصفحة يتم عبر المصادر قبل الترقيم بذاكرة heap محدودة بالمقطع المطلوب، مع بقاء العرض مجمعًا حسب المصدر.

تستعمل الأسماء البديلة المعلنة صراحة في بيانات العمل نفسه، بما فيها العربية والإنجليزية واليابانية. عند جلب التفاصيل الاختيارية تُحفظ تلك الأسماء في المرجع الأصلي في MediaLists، وتُحفظ عند تحديث الفهرس لاحقًا، وتبطل مراجعة البحث المشتقة. لا ترجمة مخمنة أو دمج هويات متشابهة، ولا شبكة عند كتابة الاستعلام. غياب aliases من المصدر يبقى قيدًا، ولا تتحول One Piece تلقائيًا إلى كل تهجئة محتملة.

## الاختبارات والملفات

تغطي الوحدات تقدمًا يتجاوز المهلة القديمة، بقاء الموصل المتوقف محدودًا، فشل السجل، HTTP429، عدم ازدواج الجلب، إلغاء المستهلك المملوك دون اليدوي، النطاق الملتبس، اختيار هويات متفرقة، إصلاح unknown-order دون رفع مراجعة اللغة، صفر اختيار، الميزانية وعضوية التشغيل، حماية ملفات التفاصيل، ودرجات البحث والأسماء البديلة دون دمج.

تكامل Electron الحقيقي داخل ملف تعريف معزول يغطي ترتيب القائمة مقابل ترتيب التنزيل، الحفظ وإعادة فتح العارض، الفصول السليمة، رفض HTML، ملفات الغلاف وإيصالاتها الأصلية، نصًا متاحًا مع غلاف معطوب، alias لعمل آخر، وتحديث MangaSpark الأصلي بعينة20492. توجد أيضًا عينتا50000 فهرس و80000 بحث في العامل. هذه اختبارات معزولة، وليست إثبات موقع حي أو Windows جديد.

## تجربة Windows المقترحة

1. استخدم Preview معزولًا ونسخة احتياطية متسقة من الملف الشخصي وهو مغلق. SQLite يظل v10، لكن Preview أقدم قد لا يفهم نمط selected وحقول السياسة الجديدة؛ لا تعدّل المخطط يدويًا للرجوع.
2. في Sites اختر MangaSpark وحده ثم Update. راقب Observed titles وآخر نجاح والعدد المحفوظ، ثم افتح Open Logs واحتفظ بملف JSONL للعملية. كرر Update All بعينة مصرح بها دون تشغيل أرشفة موقع؛ لا يعد اكتشاف20492 أو نهاية الصفحات برهان اكتمال.
3. للمواقع الفاشلة، أرسل السجل المنقح مع المعرف والتاريخ؛ قارن المرحلة وHTTP والمهلة، لا تفترض أن كل مصدر يعاني السبب نفسه.
4. أضف مانجا صغيرة إلى Downloads، وافتح Chapters. جرب Source Order ثم اتجاهًا زمنيًا مثبتًا أو أكد اتجاه المصدر يدويًا. اختر فصولًا متفرقة، أغلق البطاقة وأعد تشغيل التطبيق وتحقق من الهوية والترتيب قبل التأكيد. لا تستخدم النطاق الرقمي بلا دليل.
5. لجلسة قديمة بسبب unknown-order، حمّل القائمة المحفوظة ثم Apply Source Order to saved task أو اتجاهًا مؤكدًا، وبعده Start/Resume صريح. تحقق من ثبات الجلسة والمحاولات وعدم إعادة الصور السليمة. إذا بقيت Review، افحص اللغة/التعارض/الاستعادة بدل تجاوزها.
6. فعّل Download Manga Details لمانجا صغيرة فقط. افحص مجلد00 والامتداد والنص والحالة المستقلة. فشل المعلومات يجب ألا يحوّل فصولًا مكتملة إلى فشل. أعد الاستئناف المسموح وتحقق من إعادة استخدام الغلاف السليم.
7. ابحث باسم دقيق ثم خطأ معقول ثم alias موثق؛ الشبكة لا تُستدعى من البحث. أبلغ عن الاسم الأصلي والمصدر عند غياب aliases بدل افتراض علاقة عنوانين.
