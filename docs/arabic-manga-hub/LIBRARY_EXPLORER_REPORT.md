## السلة والتخزين والنقل

السلة توسعة لـ`hub_selections` الأصلية. تعتمد الهوية على `siteId + mangaId`؛ لا تدمج العمل نفسه من موقعين. اختيار الكل قبل تحميل الفصول رمزي وعدده Unknown. بعد تحميل القائمة، تحفظ الهويات الأصلية والاستثناءات والترتيب والاتجاه الموثوق عندما يتوفر. لا يُستنتج الاتجاه من أرقام العناوين.

يحمي revision من حفظ استجابة قديمة فوق تخصيص أحدث. إعادة تحديد عنصر موجود لا تعيده إلى الكل. تعرض الواجهة خطأ الحفظ وتستعيد الحالة المحفوظة. تغيير المصدر أو الاستعلام لا يمس النطاق. قوائم السلة تعيد عدد الفصول وملخص النطاق بدل نسخ عناوين جميع الفصول مع كل Refresh؛ تبقى النسخة الكاملة في SQLite. عرض السلة محدود بـ50 عملًا في الصفحة.

النقل معاملة مستقلة لكل عمل: إنشاء المرجع ونطاقه ثم إزالة الاختيار، أو التراجع الكامل لذلك العمل وإبقاؤه في السلة مع السبب. إذا اختلف نطاق مهمة موجودة، لا يُعد ذلك نجاحًا. التكميل الصريح يعيد استخدام `queue-supplement` ويحفظ الماضي والإيصالات والميزانية. لا تُنشأ جلسة تنزيل عند مجرد الاختيار أو النقل. يبقى `ArchiveManager` و`DownloadManager` وRecover وحماية المساحة المحرك الوحيد.

احتاجت هذه المعاملة إلى جدول SQLite إضافي؛ فصل النطاق في IndexedDB كان سيمنع الالتزام الذري مع مرجع السلة. أضيف ترحيل **v11** بعد v10، بجدول واحد:

```text
hub_selection_scopes(
  selection_seq PRIMARY KEY REFERENCES hub_selections(seq) ON DELETE CASCADE,
  revision,
  value
)
```

يحتوي value على JSON محقق بحقول محددة: mode وids وorder وdirection وchapters وسبب المراجعة عند الفشل. لم تُعدل ترحيلات v1–v10 المنشورة أو هويات الاختيارات القديمة أو جداول الملفات والمحاولات والإيصالات وعضوية التشغيل. الاختيار القديم يُقرأ كـAll/Source Order وrevision صفر. اختبارات الترقية تبدأ من v10 فعلية، وتبقى اختبارات v6/v7/v9 والاستعادة الأصلية.

تبقى حدود **5 مانجات و20 محاولة فصل تراكمية واحتياطي 50 GiB**. لا يصفرها الترحيل أو التكميل. قد يرفض Preview قديم قاعدة v11؛ الرجوع يتطلب نسخة احتياطية متسقة من ملف التعريف السابق والتطبيق مغلق. لا تعدل user_version ولا تحذف قاعدة البيانات للرجوع.

## البحث والقارئ والواجهة

يستعمل Explorer محرك `web/src/engine/search/` نفسه: Worker والتطبيع والأسماء البديلة والمطابقة التقريبية والترتيب ومراجعات الفهرس. أضيف browse لمصدر واحد باستعلام فارغ، دون تغيير دلالة البحث العادي الفارغ. تُحفظ تفضيلات Explorer في مفتاح مستقل عن Search.

أثبت اختبار Electron تصفح 20,492 عنوانًا محليًا مع 25 صفًا فقط ودون طلبات للمصدر. الفصول تُجلب عند فتح العمل صراحة. الطلب القديم لا يكتب فوق العمل الجديد؛ المعاينة تستخدم القارئ الأصلي بعزل تنقل الفصل التالي عن Media List. لا تتغير اختيارات السلة بسبب عرض صورة أو فشلها.

تستعمل Open Manga المعرفات الأصلية. وتشتق Open Folder مجلد العمل في Electron من الجذر والإيصالات أو شاهد الهوية؛ المجلد الغائب أو المتعارض يعطي رسالة واضحة. تبقى وظائف المفضلة والتنزيل الأصلي وMedia List مستقلة.

## صفحة المعلومات والتحرير

الهيكل الجديد:

```text
Manga/
  00 - Manga Details.html
  00 - Manga Details/
    identity.json
    metadata.json
    cover.png أو الامتداد الحقيقي
    cover-<id>.png
    details.txt
    backup-<id>.dat
    edit-journal-<id>.json
    edit-complete-<id>.json
  ...chapter outputs...
```

HTML الرئيسي وحده يعاد توليده الآن، بمسارات نسبية، دون سكربتات أو موارد شبكة، ومع escaping وCSP. إذا وجدت صفحة `00 - Manga Details/index.html` من Preview قديم تبقى محفوظة كما هي؛ لا تُولد نسخة ثانية جديدة ولا يُحذف ملف قديم. لا يعتمد التصميم على فرض ترتيب الملفات والمجلدات في Windows Explorer.

المحرر يدعم العنوان والعناوين البديلة والقصة والتصنيفات والحالة والنوع والمؤلف والرسام والغلاف. اختيار الصورة عبر Dialog أصلي، مع تحقق Electron من المحتوى والحجم والأبعاد. لا يتغير اسم مجلد الفصل أو هوية المصدر بتغيير العنوان التعريفي.

Save يفحص بصمتي JSON وHTML بعد عرضهما. أي تعديل خارجي يرفض الحفظ ويطلب Reload. يلزم تأكيد يحفظ نسخًا احتياطية قبل استبدال الملفات. أما Regenerate from saved JSON فيقرأ JSON الحالي صراحة، ويحافظ على التعديل اليدوي، ويعيد توليد الصفحة؛ لا يفترض إمكانية جلب JSON عبر file://.

تُجهز الملفات قبل نشرها، وتبقى النسخ والملفات المرحلية وسجل edit-journal عند الانقطاع. توصف العملية Partial عند إمكان تحديث SQLite، ويعرض Read تحذيرًا للسجل غير المكتمل. لا يُدّعى وجود معاملة ذرية عبر جميع الملفات أو قفل يمنع كل تطبيق خارجي. فشل المعلومات لا يغير نتيجة الفصول.

يتقدم ملخص القصة الحقيقي الوصف التسويقي. تشمل مصادر الغلاف الصورة الرئيسية وsrcset وdata-src وdata-lazy-src وOpenGraph وTwitter وJSON-LD المرتبط بنفس العمل. يجرب أفضل srcset معلن أولًا، ضمن خمسة مرشحين ومهلة إجمالية 15 ثانية وحد 2 MiB للصفحة و8 MiB للصورة. تبقى كل محاولة مستقلة عن الفصول. لا تُختار صورة عشوائية من الإنترنت. عقد MediaLists الحالي لا يوفر صور فهرس دائمة موثوقة، لذلك لم تُنشأ فهرسة أغلفة جماعية إضافية.

## استقرار الفهرسة والتحقق البشري

يعيد Madara محاولة الصفحة نفسها حتى ثلاث محاولات إجمالًا عند 502/503/504/521، بتأخير ثانية ثم ثانيتين. لا يتقدم رقم الصفحة عند الفشل، ولا يعيد الصفحات المقبولة خلال تلك المحاولة. لا يعيد محاولة 403 أو429 بصورة عدوانية. إذا انتهت المحاولات تبقى الملاحظات الصحيحة Partial والفهرس القديم محفوظًا.

لا يوجد استئناف دائم موثوق من منتصف Madara: تغير الفهرس قد يزيح الصفحات. بعد إغلاق التطبيق يبدأ اجتياز آمن جديد مع حفظ الفهرس المقبول؛ لا يدّعي هذا توفير cursor ثابت.

`CatalogVerification` يربط Request بعينه وAbortSignal المالك بسياق الفهرسة. لا يخطف طلبًا يدويًا لمجرد تطابق المضيف. يشمل التهيئة القياسية وتهيئات MangaLink/MangaStarz/Mangalek الموسومة. لا يُعد403 أو521 أو انتهاء مهلة دليل CAPTCHA.

بعد كشف Interactive، لا تجدد أحداث DOM مهلة الستين ثانية. فحص زوال التحدي يقرأ DOM دون سلسلة طلبات جديدة. نجاحه يستأنف الطلب؛ وانقضاء الدقيقة يغلق النافذة فعليًا قبل التأجيل. إذا تعذر الإغلاق تبقى ملكية النقل معلقة وانتظار التسوية ظاهرًا، دون بدء مصدر جديد على موارد غير محررة.

يجمع Sites المؤجلين وعددهم. Verify إجراء صريح ونافذة مستقلة واحدة. اكتماله يجعل المصدر Ready ولا يقاطع المصدر الجاري. يستهلك المدير queued قبل ready، وينتهي Waiting بدل حلقة دائمة. إذا كانت الدورة متوقفة في Waiting يلزم Resume Update صريح. بعد إعادة إنشاء renderer تعود Ready القديمة إلى Verification لفحص الجلسة مجددًا دون تشغيل تلقائي. الإلغاء يمنع جاهزية متأخرة من إحياء المهمة. التأجيل ليس خطأ موصل يستهلك ميزانية الفشل.

**القيد المتبقي:** تحديات HTTP المجردة وتهيئات الموصلات غير الموسومة تحتاج ربطًا إضافيًا قبل ضمان هذا المسار. تبقى Review أو انتظارًا آمنًا؛ لا ندعي أن جميع تحديات كل موصل أصبحت قابلة للتأجيل أو أن CAPTCHA حيًا اختبر آليًا.

## التحقق ونقطة المراجعة

- الوحدة: 2364 اختبار web و122 اختبار Electron واختبار NW واحد ناجحة؛ ستة اختبارات متخطاة أصلًا.
- تكامل Electron/Classic/IPC/SQLite/IndexedDB: 219 تحققًا، تشمل التصفح الكبير، نطاق 2/3 محفوظًا عبر المصادر وإعادة إنشاء renderer، والقارئ والتكميل وOpen Folder ومحرر المعلومات والغلاف وJSON اليدوي وHTML المعزول.
- الاستعادة الأصلية: 31 تحققًا عبر Electron، تشمل SIGKILL والإيصالات والميزانيات.
- التحقق البشري: وقت افتراضي لمهلة الكشف وزوال التحدي، وعدم خطف الطلب اليدوي، وانتظار الإغلاق وسباق التخصيص؛ وتكامل IndexedDB لستة مؤجلين واستعادتهم وإلغائهم.
- MangaSpark: شيفرة Madara الأصلية مع 20,492 عنوانًا وخطأ521 في الصفحة61 بعد15,250 عنوانًا. أعيدت الصفحة61 فقط دون تكرار الصفحة0 أو فقد العناوين.
- نجح الفحص الساكن وبناء جميع المساحات. اجتازت الحزمة المحلية ذات الواجهة المضمّنة 24 تحققًا على Linux، بما فيها إعادة التشغيل وعزل البيانات. هذه ليست شهادة Windows؛ يبنى Preview النهائي ويختبر من الالتزام النهائي على Windows CI.

أول تشغيل Windows عند `ea997fc3` اجتاز الوحدة والفحص الساكن والاستعادة، ثم توقف اختبار الواجهة بعد فحص الغلاف عند انتظار Open Folder. كانت محاكاة `shell.openPath` تشترط مساواة النص مع مجلد الاختبار غير المطبع، رغم أن التطبيق يمرر المسار الحقيقي. صُححت المحاكاة لتقارن realpath للطرفين وهوية الجهاز والدليل معًا، وتعلن فقط نتيجتي الهوية وتساوي الكتابة دون كشف المسارات. لم تتغير حماية مسارات الإنتاج أو مهلة الاختبار. أُعيدت اختبارات التكامل محليًا ونجحت التحققات الـ219. يبقى إثبات Windows تابعًا للتشغيل الجديد؛ لا تُعد نتيجة التشغيل الأول حزمة قابلة للتسليم.

المصادر الحية غير متاحة ضمن سياسة شبكة البيئة. لا دليل جديد على إصلاح صور MangaLink أو أخطاء403/404 لبقية الموصلات، أو نجاح CAPTCHA حي. نجاح الفهرسة أو النقل المعزول لا يثبت سلامة الصور أو اكتمال المصدر. خارطة الأرشفة الشاملة باقية مفتوحة.

### تجربة Windows

1. استخرج Preview في مجلد جديد؛ احتفظ بنسخة متسقة من بيانات Preview السابق ولا تستعمل بيانات HakuNeko الأصلي.
2. جرّب Open Manga وAdd to Queue في Search، ثم Multi-select واختر عملًا.
3. افتح Explorer وحدد المصدر والعمل، واستبعد فصلًا، وبدّل المصدر وارجع. جرّب العين ثم Back to Explorer والسلة المجمعة وUnknown.
4. انقل إلى Downloads وراجع النطاق. التكميل يحتاج تأكيدًا منفصلًا، والبدء يحتاج Start.
5. نزّل عينة صغيرة مسموحة، ثم Open Folder وEdit Manga Info وغلافًا محليًا. افتح HTML دون إنترنت وعدّل JSON ثم Regenerate.
6. عند تحدٍّ بشري مدعوم، اختبر التأجيل وVerify وResume دون ضغط أو تجاوز حماية، وشارك JSONL منقحًا عند الفشل.

المتابعة بعد المراجعة: توسيع تبني ملكية النوافذ للتهيئات المخصصة عند توفر أدلة حية، وإصلاح الموصلات المحددة، وتحسين ترميم تحرير المعلومات المنقطع. لا إزالة للحدود ولا أرشفة مواقع غير محدودة أو إصدار Windows نهائي.
