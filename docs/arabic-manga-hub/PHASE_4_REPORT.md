# المرحلة الرابعة — البحث المشترك المحلي

2026-11-06 — الفرع `feature/arabic-manga-hub`، أساس التنفيذ `d830c9bcb64625d6359f5aedfec0649c0fbf47f6`.

## ما يعمل فعليًا

قسم البحث المشترك داخل Arabic Manga يبحث في قوائم المصادر المقبولة محليًا. لا يستدعي FetchMangas ولا يبدأ تحديث الفهارس عند الكتابة أو فتح الصفحة. تشمل المصادر موصلات MangaPlugin المسجلة التي تحمل وسم العربية فعليًا؛ تعدد اللغات وحده لا يكفي. يجمع النتائج بحسب المصدر، ويحافظ على الهوية `(siteId, mangaId)` حتى عند تساوي العنوان أو معرف المانجا بين موقعين.

يدعم البحث الجزئي، وحالة الأحرف الإنجليزية، وتطبيع التشكيل والتطويل وأشكال الهمزة والألف المقصورة. التطبيع نسخة مشتقة للبحث فقط؛ العنوان الأصلي محفوظ ويظهر كما ورد. البحث التقريبي اختياري ومحدود بمسافة تحرير 1 أو 2 واستعلام 3–64 حرفًا؛ ليس بحثًا دلاليًا ولا يختلق أسماء بديلة. تُرتب المطابقات داخل كل مصدر بدرجتها، وتعرض الواجهة 25 صفًا في الصفحة مع مرشح للمصدر وعدد إجمالي وحالة عدم وجود نتائج.

تظهر حالة تحديث المصدر وآخر نجاح وعمر الفهرس والتغطية ودليلها. الفهرس أقدم من سبعة أيام، أو بلا تاريخ نجاح، أو ذو حالة غير ناجحة يُوسم للمراجعة، ولا تُحجب نتائجه القديمة. نجاح تحديث قائمة العناوين لا يثبت سلامة الصور أو اكتمال فصول الموقع.

زر فتح المانجا يتحقق محليًا من وجود مرجعها الحالي ثم يختار الموصل الأصلي وينشئ كائن المانجا الأصلي. هذه النقرة الصريحة قد تجلب قائمة الفصول عبر Media List المعتاد؛ لا تنزل صورًا أو تضيف مهمة تنزيل. خطأ المصدر يظهر في المسار الأصلي، ويظل البحث متاحًا عند العودة. يُحفظ الاستعلام والمصدر والصفحة والبحث التقريبي والقسم النشط وموضع التمرير، بما فيها إعادة فتح التطبيق.

## التخزين والتزامن

يبقى `Store.MediaLists` مصدر الحقيقة الوحيد، مع قراءة `SiteIndexMetadata` في معاملة readonly متسقة لكل مصدر. عامل Web Worker مستقل ينفذ التطبيع والمسح والترتيب، ويعيد صفحة النتائج فقط. لا توجد نسخة مشتقة دائمة ولا مخطط قاعدة بيانات جديد: IndexedDB v6 وSQLite v8 دون تغيير.

ذاكرة مشتقة LRU داخل العامل: مصدران، وبحد إجمالي 100 ألف عنوان، وتقدير نصوص لا يتجاوز 32 MiB للمصدر و64 MiB إجمالًا. لا يُخزّن المصدر الأقدم بلا revision في الذاكرة بين عمليات البحث. تُقرأ المراجعة مع كل بحث؛ تغييرها يعيد بناء نسخة المصدر. تُراجع المراجعات مجددًا قبل نشر النتيجة؛ عند تغيرها أثناء المسح تُعاد المحاولة مرة واحدة ثم يظهر خطأ قابل لإعادة المحاولة بدل نشر نسخة غير متزامنة. إشعار BroadcastChannel بعد commit للتحديث اليدوي والجماعي وتغير الحالة يعيد البحث الجاري. الإشعار تنبيه فقط؛ التحقق بالمراجعات هو المرجع، وإعادة تشغيل التطبيق تعيد البناء من القوائم المقبولة.

فتح IndexedDB المحجوب باتصال قديم له انتظار محدود افتراضيًا بخمس ثوان ورسالة قابلة للفهم. الطلب المهجور لا يرقّي القاعدة لاحقًا بصمت: يُجهض ترحيله المتأخر أو يُغلق اتصاله. اتصالات التطبيق تغلق عند versionchange. لا حذف قاعدة بيانات أو إعادة بناء قسرية لتجاوز الحجب.

## الملفات

- `web/src/engine/search/LocalSearch.ts`: عقود النتائج والتفضيلات والتطبيع والمطابقة والترتيب.
- `SearchDatabase.ts`, `SearchWorkerEngine.ts`, `LocalSearch.worker.ts`, `SearchWorkerClient.ts`: القراءة المحلية المتسقة والعامل وRPC والإلغاء والذاكرة المشتقة.
- `LocalSearchController.ts`: حالة العرض والتفضيلات الدائمة والتأخير والإبطال والتنبيهات.
- `web/src/engine/catalog/CatalogNotifications.ts`, `SiteIndexRepository.ts`: تنبيهات التغييرات بعد المعاملات الناجحة.
- `MediaDatabase.ts`: معالجة الحجب وانتهاء الانتظار وversionchange، دون تغيير المخطط.
- `web/src/frontend/classic/components/arabic-manga/SharedSearch.svelte`, `SearchResult.svelte`, `ArabicManga.svelte` و`stores/Stores.svelte.ts`: البحث والنتائج والتنقل وحفظ الموضع. صف النتيجة مستقل لإضافة أفعال المرحلة التالية لاحقًا، دون أزرار وهمية الآن.
- الاختبارات: ثلاثة ملفات `*_test.ts` داخل search، و`test/shared-search-renderer.mjs`، وتوسعة اختبارات المركز وترحيل IndexedDB وحاضنة Electron.

## الاختبارات والقياسات

أضيف 21 اختبار وحدة للبحث والتطبيع والهويات والتفضيلات والمراجعات والإلغاء والحجب، واختبار إضافي يثبت أن تعذر إرسال تنبيه بعد commit لا يحوّل نشر الفهرس الناجح إلى فشل. تختبر حاضنة Electron العامل الحقيقي وIndexedDB والواجهة الكاملة: عدة مصادر وعنوان متكرر، عربي/إنجليزي/تقريبي، فهرس قديم ومجهول، التحديث اليدوي والجماعي، غياب المرجع، فتح المصدر والعودة، حفظ التمرير، إعادة تحميل العارض، وعدم استدعاء الموصلات أثناء الكتابة. اختبار ترحيل حقيقي يبدأ باتصال v5 محجوب ثم يستعيد v6 مع حفظ القوائم والإعدادات والصور المؤقتة؛ ويختبر إغلاق الاتصال عند versionchange دون تثبيت إصدار إضافي.

في عينة محلية معزولة من 80 ألف عنوان في مصدرين، بلغ البحث الأول 223–363 ms والمتكرر 31–38 ms في تشغيلين متتاليين. بقيت 25 نتيجة فقط في DOM؛ استمر heartbeat للعارض أثناء العمل. تقدير نصوص الذاكرة المشتقة 6,355,560 بايت. في التشغيل الأخير ارتفعت working set لعملية العارض من 270,288 إلى 320,012 KiB أثناء السيناريو؛ هذا قياس للعملية كلها وليس heap مستقلًا للعامل، ولا قياسًا للحد الأقصى أو لتسرب طويل الأمد. الأرقام على Linux/Electron في هذه البيئة وليست ضمان أداء Windows.

نتائج التحقق:

- `NODE_USE_ENV_PROXY=1 npm test`: 2421 اختبارًا ناجحًا و6 متخطاة (2322 للويب، 1 لـNW، و98 لـElectron). التشغيل الأول دون بروكسي Node فشل في اختباري GET/POST القديمين لـPostman Echo بسبب الوصول الشبكي؛ نجحا عبر بروكسي البيئة دون تغيير توقعاتهما.
- اختبارات البحث والتنبيه المستهدفة: 22 ناجحة.
- `npm run check`: ناجح عبر workspaces؛ TypeScript وESLint وSvelte وVue وقواعد المشروع. فحص Svelte بلا أخطاء أو تحذيرات، و`git diff --check` نظيف.
- `npm run build --workspaces`: ناجح، بما فيه حزمة العامل ومشروعا التطبيق والوثائق.
- `DISPLAY=:107 HARUNEKO_PRIORITY_CONNECTORS=1 node test/archive-electron.mjs`: 150 فحص renderer/IPC/واجهة/أرشفة ناجحًا؛ وتشمل اختبارات الموصلات السابقة ببيانات معزولة.
- `node test/archive-runtime.mjs`: 28 فحص SQLite/استعادة ناجحًا تحت Electron المثبت فعليًا.

الاختبارات تستخدم مصادر وقوائم وملفات تعريف معزولة؛ لا تدعي إصلاح موصل حي أو نجاح الوصول إلى موقع فعلي. لم تُختبر حزمة Windows جديدة في هذه المرحلة.

## القيود ونقطة التوقف

القائمة المرجعية الحالية مخزنة كمصفوفة لكل موقع، لذا قراءة مصدر كبير تستلزم فك مصفوفتِه كاملة في العامل؛ الذاكرة المؤقتة للمسح والفرز وSet والهياكل ليست مشمولة في ميزانية النصوص. قد يتطلب فهرس أكبر بكثير تخزينًا صفّيًا مشتقًا مرتبطًا بالمراجعات بعد قياس منفصل. البحث التقريبي محدود، والمرور عبر مصادر أكثر من سعة LRU يعيد التطبيع عند الحاجة. إشعارات تغييرات القوائم بين النوافذ تعتمد على BroadcastChannel؛ إعادة البحث تتحقق دائمًا من القاعدة حتى دون إشعار.

لم يُعدّل ArchiveManager أو DownloadManager أو SQLite أو ترتيب الفصول أو الملفات والإيصالات. تبقى حدود 5 مانجات/20 محاولة واحتياطي 50 GiB. Media List وبحث الموقع الواحد ومسار أخطاء الفصول الأصلي باقية. ميزة البحث التفاعلية الجديدة خاصة بـClassic، دون ادعاء تنفيذ واجهة Fluent لها.

المرحلة الخامسة لم تبدأ: الاختيار الدائم المستقل عن المفضلة وAdd to Queue والطابور الانتقائي، مع إعادة استخدام المحرك الحالي وحفظ المحاسبة التراكمية وعدم بدء التنزيل عند الإضافة. لا تشغيل تلقائي ولا تجاوز لبوابات ترتيب الفصول والتخزين.
