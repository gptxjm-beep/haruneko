## 2. الفهرسة الجزئية

`MangaPlugin` يوفر إشعارًا اختياريًا بمراجع صفحة الموصل الأصلية، بالإضافة إلى التقدم العددي. تستخدمه مزخرفات CSS متعددة الصفحات وMadara AJAX وDilar. `EngineArchiveSource.Catalog` يمرر هذه المراجع على دفعات50 قبل انتهاء المصفوفة النهائية، مع HTTP الخاص بالصفحة. الموصلات الأخرى تبقى على مسار المصفوفة الأصلي.

`SiteIndexManager` يتحقق من كل مرجع ثم يسجله في staging. عند خطأ لاحق قابل لهذا المسار يحفظ الملاحظات الصحيحة كتغطيةPartial وحالةReview وسبب مصنف؛ يبقى دمج الفهرس السابق وحماية تعارض تحديث يدوي ضمن معاملةIndexedDB الأصلية. ردود401/403/429 ومراجعة الهوية وأخطاء التخزين لا تبيح النشر. لا صفحات فصول أو صور تُجلب أثناء تحديث الفهرس. يبقى الطلب غير المتعاون مالكًا للقفل حتى استقراره؛ الإلغاء لا يسمح بتشغيل سلسلة شبكة ثانية فوقه.

## 3. الترتيب والتحديد وIPC

ثبت خطأ `An object could not be cloned`: مصفوفات scope المتداخلة أصبحت Proxy منSvelte عند إرسالها إلىElectron. `IPCData` يحولDTO المتداخل إلى بيانات بسيطة عند حدود `ArchiveClient.Request`، ويرفض المقابض/الدوال والدورات بدل إرسالها. لا إزالة للتحقق في العملية الرئيسية.

ثبت باختبار تراجع ترتيب15 فصلًا: عند إعادة الجلب قد يختلف ترتيب المصدر عن المعاينة؛ أصبح التنفيذ مثبتًا على `sourceIds` المحفوظة واتجاه المعاينة المؤكد قبل الاختيار والعكس. عند تغيير المجموعة الكاملة أثناء ذلك يلزم إعادة المراجعة. لا تخمين لأرقام الفصول الخاصة أو الكسور.

تظهر First→Last وLast→First في المعاينة الفعلية؛ عند غياب اتجاه موثوق يظهر اختيار مسودة وتفسير صريح حتى يحدد المستخدم أي طرف يعرضه المصدر أولًا، مع عنواني الطرفين. لا حفظ يبدو ناجحًا قبل التأكيد. Parent يعيد أخطاء الحفظ الحقيقية للبطاقة ويعيد تحميلSQLite؛ عداد generation يمنع استجابة كاش قديمة. يبقى Select All وClear Selection داخل Chapters، مع تعطيل قصير أثناء الحفظ.

## 4. إزالة/إعادة إضافة ومحاولات تكميلية

الإزالة لا تحذف جلسة أو إيصالًا أو ملفًا. إعادة الإضافة تبدأ اختيارًا جديدًا بـAll/Source Order وجلسة جديدة تُنشأ عند Start فقط؛ يُربط التاريخ بالهوية الثابتة للقائمة في settings محفوظة داخلSQLitev10. لا تعديل مخطط منشور.

التوسعة الممنوعة لmanifest قديم تعرض خيار تأكيد مهمة تكميلية مرتبطة؛ لا تغيّر manifest الأصلي. يستعمل التشغيل الجديد ArchiveManager/DownloadManager/Recover الأصليين، ويعيد استعمال الملفات التي تُفحص فعليًا. لا يبدأ فور التأكيد، ولا يضم الإضافات الجديدة إلى مجموعة تشغيل قديمة دون Start جديد.

حساب الميزانية يجمع محاولات كل الجلسات الحالية والتاريخية للعنصر، ويحسب قبول المانجا مرة واحدة عبر الجلسات المرتبطة. تبقى القيم التاريخية السابقة ولا يُعاد تصفيرها. الجلسات المفصولة لا تعمل خارج مالك القائمة. الأسماء والمسارات القائمة تبقى محمية من الاستبدال.

فحص `queue-audit` يستخدم `ArchiveFiles.Recover` فعليًا؛ يميز healthy/missing/not-written/uncertain والحالات القائمة، ولا يكتفي بحالةSQLite قديمة. ينفذ أثناء توقف القائمة؛ لا فحص متعارض أثناء الكتابة. يُمسح وصف الصحة من الكاش قبل استعماله، وتبقى إحصاءات الملفات السابقة مستقلة عن الاختيار الحالي. إذا فقد عنصرCompleted ملفًا ينتقل إلىReview، وعدّاد verified يشترط صحة الملف المسجلة بعد الفحص أيضًا. الملفات قد تتغير خارجيًا بعد أي فحص؛ يوجد Check files وإعادة تحقق عند التشغيل.

## 5. الصور والفشل والقياس

التنزيل الانتقائي متسلسل للصفحات، مع مهلة90ثانية لتحضير الفصل و60ثانية لجلب/تحقق الصفحة؛ إلغاء المالك يرفض الانتظار أيضًا. عند أول صفحة مطلوبة فاشلة يتوقف باقي الفصل بدل تجربة كل صوره المعطوبة؛ إعادة المحاولة تبقى محدودة بسياسةArchiveManager الأصلية، ثم يستمر العمل المؤهل. الصور السليمة التي جُمعت داخل محاولة فصل ناقص لا تُنشر كفصل مكتمل؛ لا كاش دائم جديد لصفحات فصول ناقصة في هذا التصحيح.

أضيف رقم الصفحة للخطأ وقياساتprepare وfetch-and-validation وtemporary-storage وexport والتأخير المتعمد عند استعماله. تحفظ مع نتيجة المحاولة ويمكن فتحها في Download Report/التصدير. الجلب والتحقق قياس مشترك هنا؛ ليس تحليلًا منفصلًا للشبكة وفك الصورة. لا رفع للتوازي أو خفض للتأخير. مسار التنزيل اليدوي الموازي باقٍ.

إذا تجاهل ناقل قديمAbortSignal فقد يظل طلبه الفعلي قيد التسوية خلفيًا؛ لا يمكن ادعاء أن المهلة أغلقت كل نقل أو نافذة داخلية. لا تُصدر نتيجة متأخرة إلى ملف الفصل. لا كتابة فوق إخراج صالح، وتظل أخطاء الصور السابقة في تاريخ المحاولات حتى مع الإلغاء.

## 6. Downloads والتقرير

البطاقات القائمة أصبحت ملخص هوية وغلاف محلي صغير ولوحة إحصاءات؛ تتكدس رأسيًا في النافذة الضيقة. الغلاف من ملف محفوظ وإيصالSHA-256 فقط، بلا طلبات شبكة عند فتح Downloads. المعلومات غير المعروفة تعرضUnknown، وعددAvailable هو الملاحظة الكاملة قبل ترشيح الاختيار؛ لا يساوي عددالفصول المسجلة بالضرورة.

Details مغلق افتراضيًا، مع بقاء خلاصة الفشل ظاهرة. `Download Report` يعرض المطلوب/المتحقق/الفاشل/Review/المعلق، والفصول وأسباب الأخطاء والمحاولات والقياسات ونتائج الكتابة والتحقق والتنظيف المستقلة. تُحفظ لقطة تلقائية في archive_events عند نتيجة المهمة وقبل فصل جلسة لإعادة الإضافة/التكميل. عرض التاريخ آخر10 لقطات، وآخر10 محاولات لكل فصل، ومعاينة1000 فصل لكل جلسة؛ العدادات تشمل الجلسة كلها. السجل الأصلي لا يُحذف.

التصديرJSON عبر Save Dialog أصلي وبإنشاء حصري؛ لا مسار منrenderer ولا استبدال ملف تقرير قائم. إعادة محاولة الفاشل اختيارية بتأكيد مهمة تكميلية وStart منفصل، دون توسيع manifest محفوظ أو تجاوز الميزانية. التقرير لا يثبت اكتمال المصدر.

## 7. معلومات المانجا المحلية

الأولوية لملخص القصة داخل حقول الصفحة قبل الوصف التسويقي العام. تبقى بقية الحقول المتاحة مستقلة: المؤلف/الرسام/التصنيفات/الحالة/الأسماء البديلة وJSON-LD للهوية المناسبة. لا استخراج شامل جديد لجميع المواقع أو اختراع غلاف/حقل غائب. حذفنا عدد الفصول المسجلة من التعريف؛ ليست صفحة تقدم تنزيل.

يحفظ المسار المحمي `00 - Manga Details` الآن metadata.json وindex.html مع TXT والغلاف المستقل. HTML دون سكربتات أو موارد شبكة، مع escaping وCSP وتخطيط يدعم العربية والأحجام الصغيرة. `RenderMangaMetadata` دالة خالصة لإعادة التوليد منJSON، مختبرة؛ JSON الموجود يبقى المدخل المفضل ولا يُكتب فوق تعديلات المستخدم. **لا محرر بيانات أو استبدال تلقائي لصفحةHTML قائمة مختلفة**؛ إعادة توليد بديل منJSON ممكنة بالدالة، أما واجهة إعادة التوليد/استبدال صفحة قائمة صراحة فمتبقية. حماية الملفات تتقدم على الاستبدال الصامت.

فشل النص أو الغلاف لا يمنع بقية المكونات أو الفصول. تشخيص الحقول الغائبة/الصورة غير الصالحة مستقل. أضيف فحص مساحة خاص بكل ملف معلومات على قرص الأرشيف النهائي، بدل احتساب حجمه فقط على قرص ملف تعريفElectron؛ القرصان قد يختلفان. لا تغيير لاحتياطي50GiB.

## 8. التحقق ونقطة التوقف

- اختبارات الوحدة الكاملة:2354 نجاحًا فيweb و1 فيNW و119 فيElectron؛6 اختبارات متخطاة أصلًا.
- اختبارات Electron/Classic/IPC/SQLite الأصلية مع نقل معزول:202 تحقق ناجح، تشمل فتح التقرير وتصديره وحماية الملف القائم وفتح HTML محلي مع الغلاف دون طلبات شبكة.
- استعادة SQLite باستخدام Electron الفعلي:31 تحققًا، تشمل SIGKILL خلال مراحل مختلفة.
- اجتاز الفحص الساكن الكامل بعد تصحيح تعريف متغير التقرير؛ Svelte دون أخطاء أو تحذيرات. اجتاز بناء جميع مساحات العمل، بما فيها التوثيق والإضافات النهائية.
- تشمل التراجعات Proxy متداخل، قائمة15 وترتيب جلب متغير، مهلة صورة لا تستجيب، فهرس200 ثم521، مهلةFetchWindow، تاريخ/ميزانية محاولة جديدة ومهمة تكميلية، فقدملف، HTML محلي محمي وescaping، وقرص معلومات مختلف.
- الاختبارات الحية للموصلات وWindows النهائي لهذه التغييرات غير مثبتة حتى اكتمالCI وتجربة المستخدم. لا يُعد نجاحLinux أو نقلHTMLمعزول نجاحًا حيًا.

### اختبار Windows المقترح

انسخ بيانات Preview احتياطيًا بصورة متسقة والتطبيق مغلق؛ لا تستخدم ملف تعريف HakuNeko الأصلي. اختبر مانجا من15 فصلًا: First→Last مع Newest first ثم Last→First؛ حدد1/2/3، أغلق البطاقة وافتحها ثم أعد تشغيل التطبيق. شغل تجربة صغيرة وتأكد من ترتيب التنزيل. احذف **ملف اختبار فقط** خارج التطبيق وافتح Check files؛ يجب ألا يبقى Verified. جرّب مهمة تكميلية بالتأكيد وStart، وافتح Download Report وصدره. فعّل Download Manga Details اختياريًا وافتح HTML دون إنترنت. أعد Full Refresh للموصلات المتعثرة بصورة محدودة وبوصول مصرح وارفق JSONL منقحًا.

نقطة العودة التالية: مراجعة هذه الإصلاحات ونتائج Windows، ثم تشخيص الوصول الحي لكل موصل، وتوسيع جودة البيانات الوصفية وتوفير إعادة توليد صريحة آمنة. تبقى الأرشفة الشاملة مشروعًا تجريبيًا مفتوحًا وفق ARCHIVING_ROADMAP؛ لا رفع حدود أو أرشفة موقع كامل هنا.
