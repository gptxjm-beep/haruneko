# المرحلة الثانية — صفحة Arabic Manga وترتيب الموصلات

2026-11-06. الفرع `feature/arabic-manga-hub`، الأساس `cc663e8f20fa51c3c3a70a85c5c45be9ac69d2e3`. تسليم للمراجعة قبل المرحلة الثالثة؛ لا دمج في master.

## ما يعمل فعليًا

- رابط Arabic Manga بجوار Archive Site في Classic يفتح صفحة كاملة مستقلة عن تحديد موقع، حتى عند إيقاف Content Panel. يوجد رجوع صريح إلى Media List، وتعود روابط Home وBookmarks وPaste Media URL واختيار الموصل إلى الصفحة الأصلية حسب وظيفتها.
- الموقع يُصنّف باللغة من Category/Title لوسم Tags.Language.Arabic، لا من حروف اسمه. موقع إنجليزي الاسم مع الوسم يظهر؛ اسم عربي بلا الوسم لا يكفي. Arabic مع Multilingual يظهر ضمن العربية؛ Multilingual وحده في قائمة منفصلة بعنوان أن العربية غير مؤكدة.
- تصفية المصدر بالاسم أو المعرّف أو المضيف، مع نتيجة فارغة واضحة وترقيم20 مصدرًا للصفحة؛ هذا حد عرض، وليس حدًا لعدد المصادر المدعومة. تُعاد الصفحة إلى الأولى عند تغيير التصفية. المركز مرتب أبجديًا.
- زر فتح قائمة المانجا يستخدم كائن الموصل الأصلي ويعود إلى Media List. لا FetchMangas ولا Update ولا تنزيل أو إنشاء جلسة عند فتح المركز أو اختيار المصدر؛ يعمل بحث المصدر وتحديثه الأصليان في مكانهما بعد الاختيار.
- Select a Plugin ونافذة Plugins يعرضان العربية أولًا افتراضيًا. خيار Arabic sites first قابل للتغيير في القائمة والمركز ونافذة الموصلات وإعدادات Interface. تعطيله يعيد المقارن الأبجدي الأصلي مع أولوية المفضلة القائمة؛ تفعيله يبقي أولوية المفضلة داخل كل مجموعة لغة. مدخل Bookmarks يبقى مستقلًا في بداية القائمة. لم ننفذ نظامًا جديدًا لمفضلة الموصلات؛ زر المفضلة الوهمي القديم في نافذة Plugins لم يُطوّر ضمن هذه المرحلة.
- التفضيل `arabic-first-plugins` ضمن نطاق `frontend.classic` يُحفظ بواسطة SettingsManager القائم في IndexedDB، ويُحمّل عند التشغيل التالي. لا مسار IPC جديد أو إعداد تنزيل عام أو ملف SQLite جديد.
- حالات المصادر: بلاغ مستخدم بتاريخ تسجيله، مع توضيح أنه لا يعمم صحة أو عطل كل الأعمال؛ أو لا تتوفر نتيجة فحص حي في المركز. لا شارات نجاح خضراء مخترعة أو عمليات فحص حي خفية.
- البحث المشترك والمكتبة والتنزيلات الانتقائية ظاهرة كأقسام غير متاحة بعد، دون حقول بحث مانجا أو أزرار وهمية أو إضافة إلى طابور غير منفذ.

## التصميم والتوافق

أضيف `UI.page` مستقل عن محتوى القارئ. يبقى MediaSelect وMediaItemSelect ومحتوى القارئ مركبًا أثناء عرض المركز، ويُخفى تخطيطه فقط؛ لا تضيع تصفية Media List أو اختيارها عند الرجوع. عند فتح موصل مختلف تُمسح اختيارات المانجا والفصل غير المتوافقة؛ فتح الموصل نفسه يحفظها. الصفحة RTL مع حقول مسماة، تركيز العنوان عند الفتح، بطاقات متجاوبة، ونتيجة تصفية معلنة لقارئ الشاشة.

منطق الوسوم والترتيب والتصفية والحالات المسجلة واختيار الموصل في ملف TypeScript مستقل عن Svelte أو طلبات الشبكة. استُخدم المسار الأصلي للموصلات والتفضيلات؛ لا محرك تنزيل ولا نموذج مانجا مركب جديد. Fluent يستمر بواجهته الحالية؛ الصفحة والتفضيل الجديدان خاصان بـClassic، ولا ندعي دعمًا تفاعليًا لهما في Fluent. بُنيت حزم الواجهتين.

كشف اختبار إعادة تركيب App أن Carbon ComboBox يرسل select عند مزامنة اختيار موجود؛ استدعاء التنقل لذلك الحدث كان يعيد المركز تلقائيًا إلى Media List. يعالج MediaSelect الحدث فقط إذا اختلف معرّف الموصل عن الاختيار الحالي، مع استمرار الفتح الصريح من المركز أو نافذة الموصلات.

SQLite باقٍ على **v8**، ولا تغيير لمحرك الأرشفة أو الملفات أو الإيصالات أو جلسات التشغيل. حدود5 مانجات/20 محاولة واحتياطي50GiB باقية، ولا تشغيل تلقائي. إصلاحات v8 لا تعتمد اتجاه موصل؛ ما زالت أداة إصلاح الجلسات القديمة واعتماد الاتجاهات مطلوبة.

## ما بقي للمرحلة الثالثة

فهرسة المصادر وتحديثها متسلسلًا مع إلغاء ومهل ومحاولات محدودة، وحفظ آخر فهرس صالح عند الفشل، وتسجيل التغطية ومصدر الدليل وتاريخ النجاح والأخطاء. يلزم تدقيق Store.MediaLists وسجل الأرشفة لإعادة الاستخدام دون نسخ متعارضة؛ لا بحث شبكي مع كل ضغطة ولا ادعاء اكتمال من انتهاء المصفوفة.

البحث الموحد في المانجات والمكتبة والاختيار الدائم والطابور الانتقائي مراحل تالية، وستستخدم ArchiveManager وDownloadManager وArchiveRepository الحاليين مع القيود القائمة. حالات الموصلات المعروضة حاليًا سجل ملاحظات ثابت محدود، لا خدمة مراقبة آلية. لم نصلح MangaTek أو3asq، ولم نبدأ المرحلة الثالثة أو نُنشئ Preview Windows جديدة.
