# المرحلة الثالثة — فهرسة المواقع العربية وتحديثها الجماعي

2026-11-06 — الفرع `feature/arabic-manga-hub`، الأساس `8debdd40709e81291eeeaa43a7c73244ad341073`. فهرسة مراجع المانجات فقط؛ لا بحث مشترك أو تنزيل انتقائي في هذا التسليم.

## التصميم واختيار التخزين

دُرست `Store.MediaLists` وArchiveRepository. قوائم المحرك الحالية تُقرأ وتُكتب في IndexedDB باسم HakuNeko، بينما SQLite v8 يحفظ جلسات الأرشفة ومحاولات وملفات المحتوى في Electron الرئيسي. نقل القوائم الآن إلى SQLite مع إبقاء قارئات المحرك سيخلق مرجعين متنافسين أو يتطلب إعادة كتابة واسعة.

لذلك تبقى **MediaLists النسخة المقبولة الوحيدة للقائمة**، بمفتاح الموقع الأصلي وقيم `{id,title}` الأصلية. أضيف ترحيل IndexedDB v5→v6 في قاعدة البيانات نفسها، دون تعديل SQLite أو مخططه:

| المخزن | البيانات |
| --- | --- |
| MediaLists — قائم | المصفوفة المقبولة لكل siteId؛ المرجع الذي يستعمله المحرك والبحث المحلي اللاحق |
| SiteIndexMetadata — جديد | siteId، revision، count، lastSuccess، lastAttempt، state، error، discovered، coverage مع state/evidence |
| SiteIndexJob — جديد | آخر عملية جماعية: UUID وحالة وترتيب مواقع وميزانية محاولات لكل موقع والموقع الجاري ووقت آخر انتقال |
| SiteIndexStaging — جديد | دفعات مرشح غير منشور بمفتاح مركب attemptId/offset وفهرس attempt؛ لا تعد قائمة مقبولة ثانية |

ينشر الموقع بمعاملة واحدة تشمل القائمة والبيانات الوصفية ونتيجة موقعه في العملية وحذف دفعاته. إذا فشلت المعاملة يبقى الفهرس السابق وإيصال نجاحه. الانقطاع بعد النشر وقبل الانتقال التالي لا يعيد الموقع الناجح. تُحذف دفعات الفهرسة الخاصة بهذه الطبقة عند إنهائها أو إعادة محاولة موقع منقطع؛ لا يمس ذلك TemporaryData للصور أو ملفات الأرشيف.

الترحيل لا يحذف قوائم أو إعدادات أو بيانات صور. فُصل تعريف قاعدة IndexedDB وفتحها في MediaDatabase لمنع وجود نسختين متعارضتين من رقم المخطط. القراءة من فهرس قديم بلا metadata تستعمل عدد عناصره عند إدخاله للعملية، ولا تختلق تاريخ نجاح سابقًا.

## سياسة قبول النتائج

- استجابة ناجحة غير فارغة يمكن نشرها بتغطية unknown إذا لم تُسقط أي هوية محفوظة سابقًا. لا نستنتج complete من نجاح FetchMangas أو انتهاء المولد.
- partial أو unsupported تذهب إلى Review وتبقي القائمة السابقة، حتى لو كان المرشح أطول منها.
- الفراغ أو فقدان هوية سابقة، حتى مع زيادة العدد الإجمالي، لا يستبدل القائمة دون دليل complete صريح غير فارغ مع terminal من المصدر. لا يوفر المحول العام الحالي هذا الدليل؛ يعيد unknown دائمًا.
- دليل complete دون إشارة terminal يُخفض إلى unknown. حالة finished للعملية تعني انتهاء معالجة المواقع المحددة، ولا تثبت اكتمال فهارسها أو نجاح كل موقع.
- تكرر الهوية بنفس العنوان يُدمج؛ الهوية نفسها بعناوين متعارضة تحتاج Review. لا دمج بين موقعين ولا توليد هويات من العناوين.
- refresh اليدوي القائم يبقى قرارًا صريحًا بالسلوك الأصلي، ويحدّث revision وبياناته الوصفية في المعاملة نفسها. إذا حدث أثناء جلب مرشح جماعي، تُرفض كتابة المرشح الأقدم ويُحفظ التحديث اليدوي. سياسة التحديث الجماعي المحافظة لا تُستبدل باستدعاء Update اليدوي.
- الأخطاء المخزنة رموز وتصنيفات ثابتة؛ لا تُحفظ رسالة الاستثناء الأصلية أو URL موقع مع استعلامات أو Cookies أو Authorization أو أجسام HTML.

## المدير والتوقف والاستئناف

SiteIndexManager منظم قوائم، وليس محرك تنزيل. يستعمل Catalog من EngineArchiveSource الذي يستدعي FetchArchiveEntries الأصلي. لا يستدعي Chapters أو FetchPages أو FetchImage أو DownloadManager، ولا يكتب في ArchiveRepository.

المصادر الافتراضية هي MangaPlugin المسجلة ذات وسم Arabic الصريح. Multilingual وحده خارج العملية؛ Arabic مع Multilingual مؤهل. تعرض الواجهة عدد المصادر المؤهلة وسبب عدم أهلية موصل لا يملك قدرة فهرسة المانجا، بدل اختباره كأنه معطل حيًا.

هناك Web Lock حصري عبر نوافذ الأصل نفسه، مع ملكية محلية وسجل دائم. لا يمكن فتح عملية جديدة فوق running/paused/interrupted؛ الاستئناف أو الإلغاء قرار صريح. تهيئة العرض مشتركة بين مرات الفتح ولا تبدأ شبكة، وتنتظر الأزرار تحميل السجل قبل إتاحتها.

السياسة الحالية: موقع واحد في المرة، محاولتان كحد أقصى للموقع في العملية، مهلة60 ثانية للمحاولة، ثانية بين المواقع، وثلاث ثوانٍ قبل إعادة المحاولة. القيم في عقد المدير قابلة للضبط هندسيًا؛ لا إعداد Unlimited أو تغيير لحدود الأرشفة.

- فشل شبكة عادي ينهي طلبه: إعادة محاولة محدودة ثم انتقال للموقع التالي. فشل التخزين لا يعيد جلب الموقع بلا داعٍ؛ إن تعذر أيضًا حفظ الخطأ تتوقف العملية وتبقى للاستعادة.
- Pause يحفظ التقدم ولا يعيد المواقع الناجحة عند Resume. الإيقاف المتعمد لا يستهلك محاولة فشل؛ المحاولة التي انتهت بالفعل بمهلة لا تُسترد إذا طلب المستخدم الإيقاف بعدها.
- Cancel يحفظ حالة نهائية لهذه العملية ويترك القوائم المقبولة والتنزيلات اليدوية والأرشيفات كما هي. النتيجة المتأخرة لا تنشر فوق حالة الإلغاء.
- بعض FetchMangas القديمة لا تقبل AbortSignal فعليًا. عند الإلغاء المنطقي تُسجل الحالة فورًا، لكن يبقى القفل حتى ينتهي الطلب الداخلي؛ لا يبدأ موقع آخر بالتوازي معه. عند مهلة فقط، يمكن للعملية المطلوبة أن تتابع تلقائيًا بعد انقضاء الطلب القديم ضمن المحاولتين. إذا طلب المستخدم Pause/Cancel خلال الانتظار فلا متابعة تلقائية. إن لم ينته الطلب يلزم إغلاق التطبيق قبل محاولة استئناف جديدة.
- بعد إغلاق العملية دون إنهاء، تسجل التهيئة Interrupted وReview للموقع الجاري. Resume يعيد هذا الموقع من بدايته لأن الموصل العام لا يعرض cursor موثوقًا، ويحفظ المحاولة المنقطعة ضمن الميزانية. إذا استُنفدت المحاولتان يصبح Review دون طلب إضافي. المواقع الناجحة لا تعاد.
- إغلاق صفحة المركز وحده لا يوقف مديرًا بدأه المستخدم. إعادة فتحها تراقب الكائن نفسه. لا بدء أو استئناف آلي عند تشغيل التطبيق.

## الأداء وحدود التوافق

التحقق والتحويل والنشر المرحلي على دفعات500 مرجع، مع إتاحة دورة العارض وتحديثات تقدم مخففة التكرار. لا تحتفظ الواجهة بمصفوفة مانجات جميع المواقع، ولا يحتفظ المدير بمحاولات تنزيل مكتملة. يتوقف المرشح عند تعارض الهوية أو إشارة إلغاء، وتُعزل النتيجة المؤقتة عن الفهرس المقبول.

هناك حد توافق معلوم: FetchMangas العام يعيد قائمة كاملة، وMediaLists يخزن مصفوفة لكل موقع. لذلك يبقى استهلاك ذاكرة بحجم قائمة الموقع الجاري، وتحتاج الكتابة النهائية مصفوفة محلية واحدة. ليس هذا تنفيذ بحث صفوف دائمًا أو ضمان أداء لكل حجم. المرحلة الرابعة يمكنها بناء فهرس بحث مشتق في عامل خلفي من MediaLists مع revision لإبطاله، دون جعله مرجعًا ثانيًا أو الاتصال بالشبكة عند كل بحث.

يبقى مخبأ كائنات المحرك في MangaPlugin للواجهة الأصلية. النشر الجماعي يعلّمه قديمًا؛ عند العودة إلى Media List أو اختيار الموصل يُحمّل من القائمة المحلية المقبولة على دفعات، دون إعادة جلب الموقع. لا تُحمّل كل قوائم العمليات الناجحة ككائنات عرض إضافية من المدير.

## الواجهة

أضيف Update All Arabic Sites وأزرار الإيقاف والاستئناف والإلغاء، مع المنجز والمتبقي وحالة العملية. لكل مصدر مُدار: الحالة بالعربية، العدد المحفوظ والمكتشف، آخر نجاح ومحاولة، تغطية **الفهرس المحفوظ** ودليلها، وسبب خطأ منقح. تظل ملاحظة صحة الصور المبلغ عنها منفصلة؛ نجاح فهرسة المصدر لا يعني سلامة الصور أو الفصول.

عند بقاء نقل قديم بعد إلغاء منطقي يظهر سبب الانتظار؛ لا تعطي الواجهة إذنًا بتحديث متعارض. صفحة المركز ما زالت كاملة وRTL؛ البحث المشترك والمكتبة والتنزيلات الانتقائية ليست وظائف متاحة بعد.

## التأثير على الأرشفة والخطوة التالية

لا تعديل في SQLite v8 أو ترحيلاته أو ترتيب الفصول أو إيصالات الملفات أو ArchiveManager أو DownloadManager. حدود5/20 واحتياطي50GiB باقية. أخطاء الصور في MangaTek و3asq واعتماد اتجاهات الموصلات وأداة إعادة ترتيب الجلسات تبقى مفتوحة في خارطة الأرشفة.

المرحلة الرابعة بعد المراجعة: بحث محلي مشترك في الفهارس المقبولة، بمفتاح siteId+mangaId، مع ترقيم/عامل خلفي للأحجام الكبيرة وإظهار عمر الفهرس وتغطيته. لا جلب شبكة مع كل ضغطة ولا دمج تلقائي للعناوين المتشابهة. لم يبدأ ذلك أو الطابور الانتقائي أو إصدار Windows جديد هنا.
