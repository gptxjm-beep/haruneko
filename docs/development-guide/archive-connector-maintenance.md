# متطلبات صيانة الموصلات المرتبطة بالأرشفة

هذا تقرير فجوات تعاقدية للمرحلة الرابعة، وليس قائمة مواقع ثبت تعطلها. لم يُعدل أي موصل، ولم تُجرَ أرشفة حية.

| القدرة | الواجهة الحالية | المطلوب من صيانة الموصل |
| --- | --- | --- |
| اكتمال فهرس المانجات | `FetchMangas` يعيد مصفوفة بلا دليل اكتمال | بيان دعم الفهرسة، وصفحات قابلة للانتظار والإلغاء، ودليل النهاية والتغطية والقيود |
| اكتمال قائمة الفصول | `FetchChapters` يعيد مصفوفة | دليل اكتمال الصفحات والتعامل مع الفصول المقيدة؛ غيابها يبقى unknown |
| ترتيب الفصول | عقد الأحدث أولًا؛ بعض الموصلات يعكس المصدر داخليًا | اختبار التزام الموصل بالعقد؛ لا يُصلح المدير خلافه بتخمين أرقام العناوين |
| اللغة | علامات عامة أو علامات فصل قد تكون غائبة | هوية مستقرة لكل نسخة لغوية وبيانات لغة واضحة، خصوصًا عند اشتراك نسختين في ID |
| عدد الصفحات | طول قائمة أعادها الموصل لا يثبت عدم نقصان المصدر | عدد مستقل موثوق ودليل مصدره عندما يتوفر |
| حدود الطلبات والذاكرة | بعض العمليات تنفذ عدة طلبات وتعيد مصفوفة كاملة | API متدفق مع إلغاء وتأخير وحدود صفحات؛ الحفاظ على حدود الموقع القائمة |

بالنسبة لأي موصل يستخدم العقد الحالي فقط، لا يمكن إثبات الفهرس الكامل من قيمة الإرجاع وحدها. هذا لا يثبت أن الموقع ناقص أو أن الموصل معطل. يوفر `ArchiveSource` مسارًا عامًا لإضافة الأدلة لاحقًا، دون استثناءات مرتبطة بأسماء مواقع داخل ArchiveManager.

أحداث `unsupported` و`unknown-order` و`identity-conflict` و`access-restricted` والقوائم الجزئية/الفارغة هي مدخلات للمراجعة والصيانة اللاحقة. لا تعني إذنًا لتجاوز حماية المواقع أو الوصول المقيد.
