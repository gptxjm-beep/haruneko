# المرحلة السادسة A — تشخيص الموصلات العربية ذات الأولوية

الفرع `fix/arabic-connectors-priority` مبني على `708a8f6294db080f2f9a3cae703057cbab3e9378`. النتائج أدناه تفصل عيوب الشيفرة المثبتة محليًا عن بلاغات الاستخدام الحي غير المعاد إنتاجها.

## الوصول وحدود الدليل

أُجريت محاولة GET محدودة لكل من `https://mangatek.com/` و`https://3asq.online/` عبر وكيل البيئة المهيأ. رفض الوكيل CONNECT بـ403؛ أعاد curl الرمز 56 وHTTP 000. لم يصل اختبار إلى خادم الموقع أصلًا. لم تُبدّل المسارات أو الوكلاء ولم تُستخدم وسيلة لتجاوز سياسة الوصول أو CAPTCHA. لم تُحفظ صفحات حية أو Cookies أو Authorization أو روابط موقعة.

بالتالي لا توجد قياسات حية لحالة HTTP أو MIME أو توقيع البيانات أو أبعاد صفحات Bleach وBoy’s Abyss، ولا مقارنة حية بين خوادمهما أو التحويلات أو متطلبات Referer. جميع HTML والصور وأسماء المضيفين المستخدمة في الاختبارات أدناه بيانات مصطنعة ومعزولة، وليست لقطات تدعي تمثيل HTML الحالي للموقعين. نسخة Windows التي أبلغ عنها المستخدم ليست بناءً محدد الهوية؛ قد تختلف عن المصدر الحالي الذي يتضمن ValidateImage من المراحل السابقة.

## سياسة استخراج الصور

`ReaderImageLink` مستخرج اختياري مشترك بين الموصلين فقط:

1. يختار `data-src` أو `data-lazy-src` الصالحين بعد تقليم الفراغات، محافظًا على الأولوية السابقة لـdata-src.
2. يفك `data-srcset` ثم `srcset` إلى مرشحين ذوي واصفات عرض w أو كثافة x، ويختار أعلى دقة من مجموعة متجانسة. لا يقسم الرابط عشوائيًا عند الفاصلة داخل query. المجموعات المختلطة أو الواصفات غير الصالحة لا تتحول إلى طلبات تخمينية.
3. يستخدم src الصالح كبديل؛ ويرفض المصدر الفارغ أو غير المدعوم بدل تحويله إلى رابط HTML الفصل أو قبول data-placeholder.

تظل الصفحات حسب ترتيب DOM؛ لا فرز بأسماء الملفات، ولا حذف لعناصر متكررة لمجرد تساوي رابطين؛ فقد تكون مقصودة. يحتفظ مسار MangaLover القائم بمعالجة proxies المعروفة، ولا يضيف هذا الإصلاح أي آلية وصول جديدة. Referer هو صفحة الفصل كما في العقد السابق، ولم تُضف استثناءات بحسب اسم المانجا أو المضيف.

المستخرج يقبل مصادر HTTP(S) المطلقة أو النسبية؛ لا يدعم صورًا حقيقية مضمنة حصريًا في data/blob. كذلك لا يتعرف على كل placeholder ذي رابط HTTP أو HTML ينتجه JavaScript لاحقًا. لا يُفعّل على موصل آخر دون دليل واختبار. لم تُغير صيغة الصورة أو ضغطها أو وحدات البكسل أو منطق ValidateImage؛ الأخير يظل صاحب قرار قابلية فك البيانات.

## اختبارات التكامل

ناقل الاختبار `arabic-priority-runtime.mjs` يستخدم FetchProvider المشترك للتحليل والتحقق، ويرجع استجابات مصطنعة من خريطة مغلقة؛ أي طلب غير معرف يفشل ولا يُرسل إلى الشبكة. يستعمل الاختبار نفس FetchConcealedRequest المستخدم في Electron لفحص تمرير Referer دون إرسال هذه الرؤوس خارجيًا. التحويل في إحدى العينات عبارة عن final URL مصطنع، وليس اختبارًا حيًا لسلسلة تحويلات HTTP.

تغطي عينة Electron:

- DOM حقيقي لصورة src ثم data-src ثم data-lazy-src ثم srcset، مع الترتيب الصحيح وصور PNG صالحة معلنة جزئيًا كـtext/html.
- رفض HTML معلن كصورة، ورفض HTTP 403 مصطنع عبر المحقق القائم، وقبول PNG على مضيف مستقل ذي MIME غير دقيق.
- أبعاد 20×2000 وCSS المعاينة الحقيقية دون تعديل العارض.
- HTML AJAX لـ364 فصلًا، وترتيبها الأحدث أولًا، ومرورها في EngineArchiveSource مع بقاء اكتمال المصدر unknown.
- إلغاء طلب صورة بدأ بالفعل ثم نجاح طلب جديد مستقل.
- تنزيل أربع صفحات وتصديرها والتحقق منها عبر DownloadManager الأصلي، ثم إعادة استخدام الناتج السليم بواسطة ArchiveManager.
- فشل فصل يحتوي HTML دون اعتباره تنزيلًا أو تصديرًا ناجحًا.
- اختبارات الأرشفة والواجهة السابقة، وحماية المساحة، والصيغ الأربع، واستعادة العارض والتحقق من أصل نافذة IPC.

تشغيل الاختبار المعزول من جذر المستودع:

```sh
DISPLAY=:102 HARUNEKO_PRIORITY_CONNECTORS=1 node test/archive-electron.mjs
```

يلزم DISPLAY صالح على Linux؛ الرقم مثال لبيئة الاختبار فقط. ناقل الموصلات لا يُضمّن في التطبيق الإنتاجي، ويظل وضع اختبار Electron العادي متاحًا دون هذا المتغير.

## الملفات الجديدة والمعدلة

- `MangaTek.ts` و`MangaLover.ts`: تفعيل مستخرج الصور الاختياري فقط.
- `websites/decorators/ReaderImage.ts`: اختيار المصدر وتحليل المرشحين؛ دون طلبات أو تعديل DOM.
- `websites/decorators/WordPressMadara.ts`: معامل extract اختياري في FetchPagesSinglePageCSS والديكور؛ الافتراضي السابق محفوظ.
- `ArchiveWorkRepository.ts`: إبقاء Cancelled عند وصول Failed متأخر وحفظ الحدث؛ لا تغيير لمخطط SQLite أو ميزانيات التشغيل.
- `ArchiveUIController.ts`: حفظ سبب فشل منقح بدل رسالة عامة تمحو أصل الخطأ.
- `ArabicConnectorsPriority_test.ts` و`archive/ArchiveUICancellation_test.ts`: اختبارات التراجع المحلية.
- `test/arabic-priority-{plugin,runtime,renderer}.mjs` وربط اختياري في `archive-electron.mjs` و`archive-electron-entry.mjs`: اختبار DOM والمحرك وSQLite داخل Electron.
- `web/scripts/arabic-connector-inventory.mjs`: حصر AST ثابت قابل لإعادة الإنتاج دون تشغيل أي موقع.
- هذا التقرير و[تقرير صيانة الموصلات](./archive-connector-maintenance.md): الأدلة، والحصر الكامل والأولويات للمرحلة السادسة B.

## القيود والخطوة التالية

تحتاج البلاغات الحية الثلاثة إلى مقارنة قبل/بعد على مصادر مسموح الوصول إليها، مع تحديد الفصل ورقم بناء Windows، وقياس status/MIME/signature والأبعاد دون حفظ أسرار. لا تُعد هذه المرحلة إثباتًا لصحة الموقعين الحيين أو اكتمال فهرسهما.

حصر الصيانة وجد 59 موصلًا فعليًا مسجلًا (30 يذكر العربية، 35 متعدد اللغات، والتداخل 6). تعدد اللغات وحده لا يثبت العربية. يعطي التقرير الجامع أسماءها وروابطها وتعريفات الاختبارات وحالة الدليل وأولويات P1/P2/P3؛ لا يصف أي موصل آخر بأنه يعمل أو معطل دون اختبار. تبدأ السادسة B بعينات صغيرة من بقية المصادر العربية وبنى الاستخراج المماثلة، ولا توسع الإصلاح الحالي تلقائيًا إلى كل Madara.

لم تُزل حدود 5 مانجات و20 محاولة أو حماية مساحة التخزين، ولم تُجر أرشفة حية أو كتابة إلى بيانات مستخدم، ولم يُنتج إصدار Windows. الاختبار الفعلي هنا Linux/Electron 45.2.2؛ Windows وmacOS غير مختبرين لهذه التغييرات. تُحفظ الالتزامات على فرع مستقل ثم يتوقف العمل للمراجعة.
