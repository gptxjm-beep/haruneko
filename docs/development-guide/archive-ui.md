# المرحلة الخامسة B — واجهة Smart Site Archiver

الفرع `feature/archive-ui` مبني على `7df6356e01bd62a42df8dd989300e9c4ab2fcea2`. لا يوجد دمج في master أو تغيير لحدود التطوير أو إصلاح للموصلات.

## تدفق الاستخدام

1. في Classic، يقع **Archive Site** بعد **Paste Media URL**. تلتقط النافذة الموقع المحدد عند فتحها؛ تغيير التحديد بعد ذلك لا يغير هذا الإعداد أو هوية أي جلسة قائمة. المانجا والفصل المحددان لا يحددان نطاق الأرشفة.
2. تعرض النافذة الموقع، ومجلد الأرشيف، والصيغة RAW/CBZ/EPUB/PDF، وسياسة اللغات والتأخير والمحاولات والاحتياطي وحدود التشغيل. اختيار المجلد يتم حصريًا بواسطة منتقي Electron؛ يعود معرّف منحة واسم مجلد، دون مسار مطلق أو FileSystemHandle.
3. يتطلب **Create archive session** مجلدًا وتأكيدًا صريحًا. يسجل جلسة `Paused` وسياسة ثابتة في معاملة SQLite، ولا يجلب صورًا أو يبدأ التنزيل.
4. يبدأ **Start** التشغيل المحدود. تنتظر **Pause** اكتمال إيصال الفصل الجاري ثم تحفظ التوقف؛ يظل **Cancel** متاحًا أثناء انتظار التوقف. يستخدم **Resume** السياسة المحفوظة والاستعادة والتحقق الحاليين، دون إعادة ضبط الميزانية. يلغي **Cancel** العمل المملوك للجلسة ويحفظ الملفات.
5. إغلاق نافذة المتابعة أو التبديل بين تبويبات الإعدادات لا يوقف الجلسة. يمكن فتحها مجددًا من **Settings → Archiving**. لا يحدث بدء أو استئناف تلقائي عند فتح البرنامج أو العرض.

الإعدادات الأصلية General وInterface وViewer وTrackers تبقى كما هي؛ Archiving هو التبويب الخامس. لا توجد واجهة أرشفة تفاعلية في Fluent: تعرض نافذة إعداداته تنبيهًا صريحًا بأن التحكم متاح في Classic على Electron، دون زر أرشفة غير فعال. البيئة التي لا تملك جسر Electron تعرض رسالة واضحة؛ والمفضلة أو مصادر الوسائط غير المتوافقة لا تنشئ جلسة.

## الربط بالمحرك والسجل

`GetArchiveUIController` ينشئ مالكًا واحدًا داخل عمر العارض، مستقلًا عن مكونات Svelte. لا تحتفظ النافذة بقائمة مهام التنزيل ولا تقلد أزرار الواجهة القديمة. يستخدم المالك `ArchiveManager` الأصلي و`DownloadManager` الأصلي؛ وتُزال مراجع المدير عند انتهاء التشغيل.

- `Start` محمي بخريطة بدء ومراجع المدير النشط لمنع سباق النقرات أو الاستدعاءات المتزامنة.
- بدء جلسة محفوظة يبحث عن الموصل الأصلي بمعرّفه ضمن سجل المحرك، وليس عن الموقع المحدد حاليًا. غياب الموصل يحفظ الجلسة ويعرض خطأً بدل تبديل الموقع.
- `Pause` و`Cancel` موجهان إلى مدير الجلسة وحده؛ لا يغيران طابور التنزيل اليدوي.
- النوافذ تقرأ تقدمًا من SQLite كل 1.5 ثانية ما دامت مفتوحة. لا تتداخل طلبات التحديث داخل نافذة واحدة. قراءة الحالة لا تبدأ مهام أو تصفر العدادات.
- تعرض قائمة الجلسات 50 عنصرًا في الصفحة، بمؤشر rowid ثابت وأزرار Older/Latest، دون تجميع جميع الجلسات في الذاكرة.

أوامر IPC الجديدة محددة: `ui-preferences` و`ui-save-preferences` و`ui-create-session` و`ui-sessions` و`ui-progress`. يستمر التحقق من نافذة المصدر والإطار الرئيسي والأصل، وتسلسل الأوامر وحد الطلبات المعلقة. لا يوجد أمر SQL أو مسار أصلي قادم من حقل نصي.

## حفظ الإعدادات وحدود الأمان

ترحيل SQLite الذري إلى المخطط **6** يضيف فقط:

```sql
CREATE TABLE archive_ui_preferences (
    id INTEGER PRIMARY KEY CHECK(id=1),
    value TEXT NOT NULL
);
```

يحتوي JSON الموثق على `rootId`، والصيغة، وإنشاء مجلد الموقع، و`reserveGiB`، وسياسة التشغيل. لا يخزن مقبض ملفات حيًا أو بيانات دخول. تبقى الميزانيات والمسارات والبصمات والسجلات السابقة دون إعادة ضبط، ويفشل الترحيل دون رفع النسخة إذا تعذر إنشاء الجدول. لا يوجد ترحيل عكسي إلى 5.

تتحقق العملية الرئيسية من جميع القيم؛ الواجهة ليست سلطة التحقق:

| القيمة | الحدود |
| --- | --- |
| احتياطي وحدة التخزين | عدد صحيح من 50 إلى 4096 GiB، افتراضيًا 50 |
| عدد المانجات | من 1 إلى 5؛ جلسات الواجهة تستخدم 5 |
| محاولات تنزيل الفصول التراكمية | من 1 إلى 20؛ جلسات الواجهة تستخدم 20 |
| التأخير | من 100 إلى 60000 مللي ثانية، افتراضيًا 1000 |
| تأخير إعادة المحاولة | من 1000 إلى 60000 مللي ثانية، افتراضيًا 5000 |
| المحاولات لكل عنصر | من 1 إلى 3، افتراضيًا 2 |
| اللغات | حتى 30 رمزًا نصيًا؛ الفراغ يعني كل اللغات المعروفة |
| اللغة غير المعروفة | Review افتراضيًا أو Include بقرار صريح |

تستخدم العملية الرئيسية سياسة التخزين المحفوظة عند فتح الخدمة. تغيير الاحتياطي مرفوض عند وجود جلسات Running/Paused/Interrupted أو حجوزات كتابة حية؛ يجب إلغاء الجلسات المفتوحة أولًا. لا يمكن لنافذة إنشاء جلسة أن تغير الاحتياطي من تلقاء نفسها، وعليها استخدام القيمة المحفوظة. إعادة ضبط القيمة في الذاكرة تتم إذا رفض SQLite حفظ التغيير.

بقية الإعدادات افتراضيات للجلسات الجديدة فقط؛ سياسة كل جلسة موجودة محفوظة في `archive_runs.policy` ولا تتغير عند تعديل الإعدادات. عند إعادة تشغيل جلسة سابقة انتهى تشغيلها إلى Review/Limited/Failed/Drained، تطبق فحوص التخزين الاحتياطي العام المحفوظ حاليًا قبل الكتابة، مع بقاء سياسة العمل والميزانية الأصلية. لا يوجد خيار Unlimited، والاستئناف لا يصفر حد العشرين محاولة.

## التقدم والأخطاء

يعرض التقرير اسم الموقع ومجلد الوجهة باسمه المختصر، والمانجا والفصل الجاريين، وعدد المانجات المكتشفة والفصول المسجلة والفصول السليمة وفق آخر تحقق مسجل، وعدد Failed وReview، والبايتات ذات إيصالات تحقق محفوظة. لا يشمل عداد البايتات تقديرًا للملفات الجزئية أو مساحة مفترضة غير مقاسة.

تعرض الحالات Running / Paused / Interrupted / Limited / Review / Failed / Cancelled / Drained. حالة تعداد الفهرس منفصلة عن دليل اكتماله؛ انتهاء FetchMangas أو انتهاء العمل المحلي لا يظهر كاكتمال للموقع. المحول العام الحالي يعطي `unknown` لغياب إثبات كامل للفهرس، ويظل ذلك ظاهرًا.

خطأ التخزين يعرض رمز السبب والموقع المنطقي والبايتات المطلوبة والمتاحة والاحتياطي عندما تكون معروفة، مع تعليمات توفير المساحة أو توصيل الوجهة الأصلية ثم الاستئناف. تبقى حماية المرحلة الخامسة A فعالة؛ لا توجد كتابة غير محدودة عند فشل القياس ولا حذف تلقائي لتحرير المساحة.

يعرض السجل أحدث 100 حدث وأحدث 100 خطأ مع مراحلها؛ التاريخ الكامل يبقى في SQLite. تنقح طبقة العرض الرئيسية رسائل الموصلات من الروابط كاملة، والمسارات الأصلية، وحقول بيانات الدخول. أسماء المجلدات المختصرة المختارة مرئية لأنها لازمة لتحديد الوجهة؛ لا تعرض السجلات ملفات تعريف الارتباط أو الروابط الموقعة.

## إعادة تحميل العارض وإغلاق البرنامج

إعادة تحميل صفحة التطبيق تختلف عن إغلاق نافذة المتابعة. عند استبدال العارض أو تعطله:

- ترتفع هوية جيل العارض، وتُرفض طلباته المعلقة القديمة والطلبات أثناء الانتقال.
- تنتهي عمليات IPC المقبولة الجارية، ثم تُغلق مقابض الأرشفة وتُحرر الحجوزات المنطقية؛ تبقى الملفات الفعلية محفوظة.
- تسجل الاستعادة حالات Interrupted للعمليات التي لم تنته بصورة طبيعية، دون تصفير الميزانية أو ادعاء اكتمال الملف.
- بعد تحميل العارض الجديد تعرض SQLite الحالة المحفوظة، ولا ينشأ مدير جديد إلا عند Resume صريح.
- فشل تنظيف الانقطاع يمنع متابعة أوامر الخدمة حتى إعادة فتح التطبيق، بدل السماح بكتابات ذات ملكية غير مؤكدة. إغلاق الخدمة قابل للتكرار دون التعامل مجددًا مع نافذة Electron مدمرة.

تشمل اختبارات الواجهة مكونات Classic الفعلية مع CSS الخاص بها داخل Electron، وبيانات صور صغيرة وموصلات محلية تمنع الشبكة. تثبت الوصول للزر، والتأكيد والمنتقي، وحفظ الإعدادات من الحقول، والهوية بعد تغيير التحديد، وعدم جلب الصور عند الإنشاء، وعدم التكرار عند التحديث، وإغلاق العرض وإعادة فتحه أثناء العمل، وأزرار التوقف والاستئناف والإلغاء، وعرض نقص المساحة، وإعادة تحميل العارض دون بدء تلقائي أو تصفير الميزانية. اختبارات المستودع تغطي فشل المعاملات والترحيل والتصفح المحدود والاحتياطي غير الآمن ورفض المسارات المحقونة.

الاختبار الفعلي في هذه البيئة على Linux/Electron 45.2.2؛ لم يُنتج إصدار Windows ولم يُختبر على Windows أو macOS. لا تدعي هذه المرحلة دعم أرشفة تفاعليًا في Fluent، ولا صحة جميع الموصلات أو اكتمال فهارسها. سجل العرض نافذة تشخيص محدودة وليس أداة تدقيق شاملة. قد يظل Pause منتظرًا موصلًا لا يدعم إلغاء جلب قائم؛ يظل Cancel متاحًا وينهي المحاولة المملوكة وفق دعم المحرك. حدود قياس السعة والحجز المنطقي والتطبيقات الخارجية والصور غير المتدفقة موثقة في [حماية مساحة التخزين](./archive-storage-safety.md).

لم تُختبر مواقع حية، ولم تُصلح MangaTek أو 3asq، ولم يُحذف أو يُستبدل أرشيف مستخدم، ولم تُرفع حدود التطوير. المرحلة متوقفة للمراجعة بعد حفظ الفرع.
