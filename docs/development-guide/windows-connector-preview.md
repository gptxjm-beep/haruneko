# Windows Preview — اختبار الموصلات العربية

تحديث: راجع [تقرير تصحيح Windows CI](./windows-ci-correction.md) قبل اعتماد أي حزمة؛ التشغيل الأول المبلغ عنه فشل قبل إنتاج Artifact مختبر.

الفرع: `test/windows-connector-validation`، مبني على `83e3e69d02d199fa7999e64cdfca0cd33e2536a4`.

هذه نسخة تجريبية محدودة للتحقق على جهاز المستخدم. لا تثبت نتائجها المحلية حل الأعطال الحية في MangaTek أو 3asq، ولا تتضمن إصلاح بقية الموصلات أو إزالة حدود الأرشفة.

## الحصول على نسخة Windows

[مسار GitHub Actions الخاص بـWindows Preview](https://github.com/gptxjm-beep/haruneko/actions/workflows/windows-preview.yml) يعمل تلقائيًا عند رفع هذا الفرع إذا سمحت إعدادات المستودع. يبني Windows x64 على `windows-latest`، ثم يستخرج ZIP ويشغل **ملف EXE الحقيقي**، ويفحص Classic وSQLite وعزل البيانات وإعادة التشغيل. لا يرفع الحزمة إذا فشل هذا الاختبار. ملفات Artifacts محفوظة 14 يومًا وتتطلب صلاحية الوصول إلى المستودع.

التسلسل: افتح أحدث Run للفرع، وتأكد أن مهمة `portable-x64` خضراء، ثم نزّل Artifact باسم `HaruNeko-Enhanced-Preview-Windows-x64-<commit>`. يتضمن ZIP، وملف SHA-256، و`preview-smoke-win32.json` الذي يثبت بيئة التنفيذ والالتزام والفحوص. التشغيل الأصلي على Windows لا يُستنتج من نجاح بناء ZIP على Linux.

العمل الحالي جرى في بيئة Linux؛ لا توجد آلة Windows تفاعلية هنا. اعتماد GitHub CLI المتاح لم يثبت صلاحيته للوصول إلى API؛ لذا لا يفترض هذا التقرير أن Run بعيدًا اكتمل أو أن Artifact صار جاهزًا دون ملاحظة نتيجته. إذا لم يظهر Run أو فشل، لا تستخدم حزمة على أنها مختبرة على Windows. لا يتطلب هذا المسار دمج الفرع في master، ولا ينشئ GitHub Release. قد لا يتاح زر workflow_dispatch لملف جديد غير موجود في الفرع الافتراضي؛ البداية المقررة هنا هي حدث push على فرع الاختبار.

للبناء المحلي على Windows مع Node 24 وGit:

```powershell
git switch test/windows-connector-validation
npm install
node app/electron/scripts/package-windows-preview.mjs
$preview = Get-ChildItem app/electron/bundle/HaruNeko-Enhanced-Preview-*-win-x64-*.zip | Sort-Object LastWriteTime -Descending | Select-Object -First 1
node test/windows-preview-smoke.mjs --zip $preview.FullName
```

يتطلب التجميع شجرة Git نظيفة وملتزمًا بها. خيار `--allow-dirty` مخصص للاختبار المحلي وتظهر حالته في manifest؛ ليس بناء المصدر الملتزم الذي ينشره Actions. تنزل أداة التجميع Electron 45.2.2 Windows x64 من إصداره الرسمي وتطابق ZIP مع SHA-256 الرسمي، ثم تضم التطبيق وواجهة الويب وجميع ملفات Electron الأصلية. SQLite مدمج في Electron؛ وجوده وإمكانية الكتابة إليه يفحصان عند التشغيل، وليس اعتمادًا على Node المضيف فقط. أي addon من نوع `.node` يمنع التجميع المتقاطع من Linux بدل نسخ مكتبة أصلية لنظام خاطئ.

## التشغيل دون خلط بيانات النسخة الأصلية

1. تحقق من بصمة ZIP بـ`Get-FileHash -Algorithm SHA256` وقارنها بملف `.sha256` المصاحب.
2. استخرج ZIP كاملًا إلى **مجلد جديد قابل للكتابة**، مثل مجلد خاص تحت Documents. لا تستخرج فوق مجلد HakuNeko الأصلي أو حزمة Preview سابقة، ولا تشغل من داخل ZIP أو Program Files المقيد.
3. شغل `Start-HaruNeko-Enhanced-Preview.cmd`. يثبت المشغل مجلد البيانات قبل بدء Electron، ولا يمرر أعلامًا إضافية. لا تضف `--user-data-dir` يشير إلى نسخة أخرى.
4. اسم EXE هو `HaruNekoEnhancedPreview.exe`، واسم التطبيق `HaruNeko Enhanced Preview`، وله AppUserModelID مستقل على Windows. لا يوجد مثبت أو تسجيل اقترانات ملفات أو تعديل لإعدادات النسخة الأصلية.
5. تحفظ البيانات تحت `haruneko-preview-data` بجوار EXE: `profile` للإعدادات الأصلية الخاصة بـPreview وسجل SQLite، و`browser` لـIndexedDB والكوكيز ومخابئ المتصفح، ومجلدات مستقلة لـtemp/logs/crashes. لا تستورد أو تنسخ ملف تعريف النسخة الأصلية.
6. شغل نسخة Preview واحدة في الوقت نفسه. تُخدم الواجهة محليًا على `http://127.0.0.1:47831`؛ إذا كان المنفذ مشغولًا يتوقف التشغيل ولا يعود إلى واجهة الإنترنت. لا تغير المنفذ عشوائيًا، لأنه جزء من هوية IndexedDB الدائمة.
7. لا تضغط Archive Site في هذه التجربة. حد 5 مانجات و20 محاولة واحتياطي 50 GiB باقٍ؛ لا تُنشأ أو تُستأنف جلسة أرشفة عند التشغيل. التنزيل اليدوي مستقل عن احتياطي الأرشفة؛ اختر له مجلد اختبار جديدًا فقط.

لا يوجد توقيع إصدار خاص بمشروع Enhanced أو مثبت Windows نهائي. قد تتدخل سياسات Windows أو حماية الجهاز؛ تحقق من المصدر والبصمة ولا تعطل حماية الجهاز لتشغيل حزمة ممنوعة بسياساته. Windows ARM64 وWindows قديم غير مختبرين؛ الحزمة المستهدفة Windows x64 بإصدار نظام يدعمه Electron 45.

## لماذا الواجهة المعدلة مضمّنة؟

البناء العادي كان يشير افتراضيًا إلى الواجهة المستضافة. `prepare-preview.mjs` يبني الويب بـ`VITE_ENHANCED_PREVIEW=1`، ويضمه إلى `resources/app/web`، ويولد `preview-manifest.json` ببصمة SHA-256 لكل ملف والتزام المصدر وحالة dirty وإصدار Electron. manifest الخاص بالتطبيق يحمل `enhancedPreview: true` ولا يحتوي URL واجهة مستضافة.

يفحص PreviewRuntime الملفات قبل التحميل وعند تقديمها، ويخدم الملفات المعلنة وحدها عبر loopback دون ملفات بيانات المستخدم. غياب الملف أو تغير بصمته يفشل بوضوح. لا يطبق CLI --origin على Preview، ويُمنع انتقال النافذة الرئيسية إلى أصل آخر. المصدر المحلي ثابت بين التشغيلات. يعطل بناء Preview تسجيل Service Worker، ويمسح مخبأ العمال الخاص **بملف Preview وحده** عند البدء، دون حذف IndexedDB أو سجل الأرشفة. بذلك لا تعيد ذاكرة Worker قديمة واجهة مختلفة عن الحزمة.

يشمل بناء الويب كل المحرك والموصلات: Archive Site وArchiving، وإصلاحات MangaTek/MangaLover، وValidateImage، وعقد التنزيل والسجل والاستعادة وحماية المساحة. لا يبدأ عميل التنزيل أو ArchiveManager جديد تلقائيًا.

## اختبار الصور خطوة بخطوة

استخدم فصولًا عامة متاحة بصورة مصرح بها، وطلبات قليلة ومتباعدة. إذا ظهرت حماية أو CAPTCHA أو 403/429، توقف وسجل الحالة؛ لا تغير الرؤوس أو تستخدم وسائل وصول بديلة.

1. **MangaTek:** اختر مانجا وفصلًا قصيرًا، وسجل الاسم وعدد الصفحات الذي أعاده الموصل. قارن أول صورتين، ثم صورة بعدهما مباشرة، وصورة وسطية، وآخر صورة متاحة. افصل بين ظهور بيانات غير صورية وبين صورة صالحة طويلة بطبيعتها. جرب المعاينة ثم وضع القراءة، وسجل وضع العرض والتكبير إن بدا القياس غير مناسب.
2. **3asq / Bleach:** اختبر الفصل الذي سبق فشله إن استطعت تحديده. شخّص صورة واحدة أولًا. لا تفترض أن المضيف أو استجابة HTTP يماثلان عملًا آخر.
3. **3asq / Boy’s Abyss:** كرر نفس خطوات الصورة الواحدة للفصل السليم سابقًا. قارن hostname وstatus وContent-Type وsignature وstage؛ لا تشارك روابط الصور كاملة.
4. **قوائم 50/50:** حدّث قائمة الفصول وسجل العدد الفعلي والعناوين/الهويات العامة الأولى والأخيرة. قارن بقائمة الموقع المتاحة لك، وابحث عن رابط تحميل إضافي أو صفحة قائمة أخرى في الاستخدام العادي. رقم فصل 299 أو 116 وحده لا يثبت أن 50 عنصرًا ناقصة. لا يعتبر المصدر كاملًا من مجرد انتهاء القائمة.
5. **تنزيل يدوي صغير:** اختر RAW أو CBZ ومجلد اختبار فارغًا مختلفًا عن أرشيفاتك القديمة. نزّل فصلًا صغيرًا واحدًا، وافتح الناتج وقارن عدد الصور وترتيبها بعرض الفصل. HTML أو فشل صورة مطلوبة يجب ألا ينتجا تنزيلًا مكتملًا. لا تبدأ أرشفة موقع أو اختبار ضغط.

## تقرير تشخيص آمن

في Classic، حدد الفصل ثم افتح **Image Diagnostics (Preview)** من القائمة الجانبية. أدخل موضع الصورة بدءًا من 1 واضغط **Test one image**. يطلب الفحص تحديث قائمة صفحات الفصل ثم يجلب الصورة المحددة فقط عبر نفس الموصل وعقد الشبكة والتحقق؛ لا يضيف تكرارًا أو رؤوس وصول جديدة. قد يجري الموصل طلبات تهيئة/قائمة أو إعادة محاولة قائمة أصلًا في محركه؛ ليس المقصود ضمان طلب HTTP وحيد.

يحتوي التقرير على build commit، واسمي الموصل والفصل بعد التنقيح، والموضع وعدد الصفحات المرصود، وحالة الاستخراج، ومضيف المصدر ومضيف الاستجابة، وحالة HTTP وMIME إن توفرا، وفئة التوقيع وحجم Blob، والأبعاد عند نجاح فك الصورة، ومرحلة الفشل ورمز خطأ محدود. لا يتضمن URL كاملًا أو مسار الصورة أو query أو Cookie أو Authorization أو نص الاستجابة أو stack/raw error. الصور تفك مرة واحدة؛ قراءة التوقيع الاختيارية محدودة بأول 64 بايت. لا تُسجل التقارير تلقائيًا في ملف أو SQLite، وتُلغى المحاولة عند إغلاق النافذة.

اضغط **Copy safe report** وانسخ JSON للمراجعة، أو انسخ النص المعروض يدويًا إذا منع النظام الحافظة. راجعه قبل المشاركة، وأرفق ملاحظتك «أولى/وسطى/أخيرة» ووضع العارض ونتيجة التنزيل اليدوي. إلغاء الفحص أثناء استخراج قائمة لا يستطيع إيقاف API لا تدعم AbortSignal، لكنه يمنع طلب الصورة بعد عودة القائمة.

قد لا تتوفر حالة HTTP عند فشل DNS/TLS أو في موصل لا يمر بمسار القياس المدعوم. وفي 403 الذي يرفضه محقق الاستجابة قبل قراءة الجسم تبقى signature/bytes فارغتين عمدًا؛ لا يُقرأ محتوى الحماية لاستنتاج معلومات غير متاحة. `observedPages` ليس إثبات اكتمال صفحات المصدر.

## القيود الحالية

- اختبارات مساحات العمل والأنواع والتحليل وSvelte/Vue والبناء موثقة في تسليم الفرع؛ لا تعتمد عبارة «نجاح Windows» على مرورها في Linux.
- اختبار التطبيق المحلي الفعلي أثبت تحميل أصل loopback رغم تمرير أصل الإنترنت، وظهور Classic وArchiving والتشخيص، وSQLite وإعادة التشغيل، وعدم إنشاء جلسات أرشفة، وبقاء 50 GiB و5/20، وعدم تغيير ملف تعريف أصلي محاكى داخل مجلدات اختبار.
- كشف هذا الاختبار عيب إغلاق مبكر: إغلاق splash بعد تدمير النافذة الرئيسية كان يحاول عرض النافذة المدمرة. أضيف شرط `isDestroyed()` مع اختبار تراجع؛ لا تغيير لمحرك الأرشفة أو حذف ملفات للتعافي.
- اختبارات تشخيص الوحدة ترفض تسرب الرابط أو الاستعلام أو الرؤوس والأخطاء الخام، وتختبر MIME خاطئًا وHTML والإلغاء وعدم تكرار فك الصورة. فحوص Electron تستعمل صورًا محلية فعلية و403 مصطنعًا.
- لم تُختبر المواقع الحية هنا؛ قيد الشبكة السابق ما زال مانعًا. لم يُثبت إصلاح Bleach أو MangaTek على Windows، ولا يزال ذلك هدف تجربتك.
- ملفات المصدر الجديدة الأساسية: PreviewRuntime واختباراته، prepare-preview/package-windows-preview، windows-preview.yml، windows-preview-smoke، ImageDiagnostics واختباراته ونافذته؛ وتعديلات محدودة في Main وApplicationWindow وSidenav وindex وPage.Fetch وValidateImage وFetchProviderCommon وImageAjax.

التوقف بعد رفع الفرع؛ لا تبدأ السادسة B أو بناء إصدار Windows نهائي قبل مراجعة نتائج التجربة.
